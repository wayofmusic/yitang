# 《[活动]AI落地Live第79场》

- 日期：2026.06.06

## 我的作业

### 1、初阶题目：什么值得学

**【题目】** 听完这次分享，你觉得在 Agent 时代，哪些能力还必须由人来学、来练、来保持手感？
请结合你自己的一项能力或工作习惯，说说这件事为什么不能完全交给 Agent，你现在和 Agent 的差距在哪里，以及你准备怎么继续练这件事

**【我的回答】**

听完纪浩老师这次关于AI时代的分享，结合我自己这段时间的实战经验，我心里的感触特别深，直接开始聊聊我的作业思考吧。

在这个Agent满天飞的时代，未来AI大概率要做的事情就是信息处理，就像是IPO模型里的那个P，不管是黑盒还是白盒，信息流转交给AI去干准没错。但是，有几种能力是绝对不能丢给AI的，必须由我们自己来学，自己来练，持续保持手感。

首先就是人类和AI的对话协作能力，也就是提问和定义问题的能力。就像课里重点讲的，我们得能分得清什么只是满足好奇心的假象，什么是现实世界里真正需要解决的真实问题。

其次就是系统且专业的审美能力。你需要用这种审美去判断AI输出的结果到底行不行，能不能直接用。所以未来我们人类更多要去训练的，就是这种系统思维和高阶审美，这些注定是无法外包给AI的。

结合我自己商业演说教练的身份，我来剖析一下演说辅导和内容设计这个能力。

平时不管是自己备课还是辅导企业家学员，我都习惯先把整个内容的骨架和情绪线搭出来。这件事为什么不能完全交给Agent呢，其实很简单。AI现在一秒钟就能给你拉出一个看似完美的演讲大纲，甚至连逐字稿都能给你写得漂亮又工整。但是，商业演说的本质不是单纯的信息传递，而是信任的建立和情绪的共鸣。

AI感受不到台下观众那种期待的眼神，它不知道讲到哪句话的时候应该停顿留白，不知道哪里该把情绪彻底推上去。

这些都是现实世界里的真实锚点，是需要人在现场去感知和调整的。对于演说这种需要极强情绪调用和表达张力的事，AI最多只能提供素材和逻辑底座，那种直击人心的气场和演说美感，AI是体会不到的，这也是它目前无法替代人的地方。

我现在和Agent的差距在哪里呢。实话实说，论知识储备的广度和处理信息的速度，我已经被AI远远甩在身后了。它能瞬间帮我找到各个行业的绝佳案例，能帮我把抽象的概念具象化。但是我的优势在于，我拥有这个领域的专业审美和实战经验。

就像纪浩老师举的那个写代码和画页面的例子，虽然AI生成内容很快，但我一眼就能看出它给的演讲稿哪里太平淡，哪里缺乏说服力，哪里不符合这位企业家的个人特质。差距就在于，AI是一个不知疲倦的高效生成器，而我是那个带有明确目的，拿着高标准审美尺子去把关的导演。

那接下来我准备怎么继续练这件事呢。

第一，我要继续把AI当成我的超级助理和对练伙伴。我会把找案例，搭初步框架这些事交给它，用它来提升我解决问题的效率。但是我绝对不能偷懒，我时刻提醒自己，不能让AI总结的认知替代了我自己的真实认知。

第二，我要拼命去拔高自己的系统审美。看到好的演讲或者极具感染力的表达，我要去拆解它背后的底层规律。只有我的眼界和审美一直走在前面，我才能提出更好的问题，才能指挥AI产出更好的东西。

第三，也就是课里提到的那个必要难度理论。不管AI多么强大，我都要持续让自己脱离舒适区，保持给自己上强度。我还是要自己上台去讲，还是要面对真实的观众去感受那种压力和反馈。只有亲自在现实世界里去碰壁，去拿到结果，去复盘，才能把演说这门手艺真正长在自己身上，保持住那份谁也拿不走的真实手感。

### 2、进阶题目：问题分辨

**【题目】** 请你描述一个最近被你注意到的目标、冲动或想做的事，结合分享内容，试着判断它更像是 problem 还是 question，并说明理由。

给你一些思路：
- 这个问题的前后状态是什么
- 现实世界里的真实锚点是什么
- 谁是受益人
- 你为什么认为它值得现在就开工，或者为什么暂时不值得

**【我的回答】**

最近我有一个特别强烈的冲动，就是想搞一套自动化辅导的AI工作流，专门用来帮我们那些企业家学员梳理个人的商业IP故事，并快速生成演讲初稿。

那这到底是一个problem，还是一个单纯的question呢。结合这节课的内容我仔细盘了一下，这绝对是一个非常典型而且高价值的真problem。

我们顺着课里讲的那几个思路来拆解一下理由。

首先看有没有明确的前后状态变化。以前的真实状态是，这些老板们平时业务都特别忙，一到要憋演讲大稿子的时候就头疼，对着电脑发呆半天写不出几个字，最后搞得非常焦虑，上台也没自信。如果我把这个问题解决了，状态就会变成，他们只需要对着AI顺着我的框架聊聊天，一个小时就能把一篇逻辑严密有血有肉的初稿搭出来，他们上台演说的自信心和效率都会大幅提升。这前后的对比简直太强烈了。

接着看现实世界里的真实锚点是什么。这个锚点一点都不虚，它就是我们同道演说的线下实战特训营，就是学员们那一份份要在招商会上拿去讲的逐字稿，就是他们讲完之后台下真实的掌声和成交的转化率。它是脚踏实地踩在我们的业务场景里的。

这事儿有两个大受益人。

第一受益人肯定是我们这些企业家学员，他们省下了大量痛苦抠字眼的时间，可以把宝贵的精力全放在演说状态和情感表达的打磨上。

第二受益人其实是我和我们的教练团队，因为我们不用再去帮学员从零开始痛苦地捋逻辑了，教练可以直接在80分的稿子上做拔高，我们辅导交付的质量和效率直接上了一个大台阶。

最后看因果链和能力支撑。把演说框架变成AI能听懂的指令这件事，别人可能觉得不好弄，但对我这个既懂商业演说又实操过大量AI落地的人来说，其实因果链是非常清晰的。

我脑子里有无数个成功的演说案例和结构，我知道怎么设计合理的提示词步骤来引导AI，怎么设置防翻车的检查点，所以我的能力是完全能支撑这套方案落地的。

那为什么我认为它值得现在就开工呢。

因为如果我只是脑子里想一想，问一句AI到底能不能写好企业家的演讲稿，那这就是个满足好奇心的question。但是现在的情况是，我看到真实的学员在真实地痛苦，写不出稿子这件事就像是一个一直在让人掉血的debuff。

只要我不去解决，这个损失就会一直存在，它实打实地在消耗学员的精力，也在消耗我们教练的心血。早一天把这个AI工作流做出来，学员就能早一天脱离苦海，这种能直接改变工作现状，提升交付体验的事，晚干一天都是巨大的损失。

所以这绝对是一个值得我立刻动手去跑通PDCA的真problem。

### 3、高阶题目：防御性设计

**【题目】** 这是一道选做题。选择一个你打算让 Agent 协作完成的真实任务，写一份「开工前检查清单」。
- 请尽量包含：你要让 Agent 做什么，准备提供哪些上下文，会设置哪些检查点
- 可以尝试写：哪些结果一旦出现就要暂停或回退，你会怎么降低翻车概率，等等

**【我的回答】**

a. 明确目标：让 Agent 基于 v1.6 PRD，完成快速生成模块的前端代码重构。 #问题定义

b. 系统上下文：提供前端技术栈规范、目录结构与基础 UI 组件库文档。 #环境约束

c. 业务上下文：提供《演说大师领域知识库》，剥离原 PRD 中的非技术干扰。 #上下文提纯

关键检查点设置

a. 方案核对阶段：要求 Agent 先输出组件拆分树与状态管理方案。 #预设计验证

b. 核心逻辑阶段：要求先实现 API 数据联调测试，确认数据能正常跑通。 #打通因果链

c. 视觉还原阶段：要求分步提交页面 UI 代码，确保样式不污染全局。 #控制爆炸半径

暂停与回退机制

a. 越界暂停：一旦 Agent 提议修改数据库 Schema 或后端 API，立即暂停并需人工审核。 #防御性设计

b. 幻觉回退：若 Agent 擅自引入未定义的第三方 npm 包，直接回退并清空当前上下文。 #纠偏机制

c. 噪音干预：当单次输出包含大量无关代码重写时，打断生成并重新强调修改范围。 #降噪处理

System Profile (系统结构与技术栈自述)

a. 产品定位：全端演说能力训练工具，聚焦讲稿生成与表现测评。 #系统边界

b. 前端架构：Web (React+Vite) + 微信小程序 (原生 WXML)。 #前端约束

c. 后端架构：FastAPI + PostgreSQL，部署于 speech.xuebage.top。 #后端约束

d. 核心依赖：DeepSeek (chat/reasoner)、讯飞语音 API。 #外部依赖

Domain Knowledge (领域业务知识)

a. 讲稿生成逻辑：主题、受众、目标三要素驱动，通过 5 轮访谈输出。 #业务内核

b. 测评核心指标：台风、内容逻辑、语音表现，需转为结构化 Markdown。 #评价标准

c. 心理疏导原则：优先倾听与情绪标注，挖掘核心信念，不轻易下指导棋。 #交互基调

ForAgent: 约束与工作手册

a. 严格依从：禁止擅自修改前后端交互协议（API Contract），遇缺失向人类提问。 #权限收拢

b. 最小实现：功能开发应遵从 MVP 原则，不增加 PRD 未提及的动画或特效。 #动作变形控制

c. 状态管理：代码中的流式输出（Stream）必须包含完整的错误捕获与超时兜底。 #容错设计

d. 接口规范：所有对 AI 接口的调用，必须实现从 reasoner 到 chat 的自动降级。 #高可用策略

Deliverables (交付物定义)

a. 交互交付：实现 v1.6 版本要求的多屏适配（横屏/平板/大屏）与三态主题。 #视觉交付

b. 数据交付：保证 /api/ai/speech/quick-generate 接口调用的参数准确。 #逻辑交付

剥离“系统自述”与“领域知识”

a. 存在问题：原 PRD 将产品愿景、心理学常识与数据库字段混杂在一起。 #上下文污染

b. 优化逻辑：将抽象的业务规律与具象的技术规范彻底拆开，降低 Agent 理解难度与幻觉。 #结构重组

增加 ForAgent 约束专区

a. 存在问题：原 PRD 是写给人看的，没有告诉 AI “不能做什么”。 #边界缺失

b. 优化逻辑：补充明确的底线规则（如禁止改 Schema、必须做 API 降级），为 Agent 设定护栏。 #防御性设计

强化状态与验收标准

a. 存在问题：原验收标准偏向人类体感（如“不挤压”、“不闪白屏”），AI 无法量化。 #模糊指令

b. 优化逻辑：转化为具体的架构要求与容错策略，把“凭感觉”变成可验证的子问题。 #标准具象化
