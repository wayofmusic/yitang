# 核心模型：AI双三角（AI Dual Triangle）

这是项目成功的底层逻辑，旨在打破“人觉得AI不智，AI觉得人不懂”的认知错位。

- **人类三角（Human）：** 负责**创造力、审美（专业标准）、体系（科学管理）**。

  - *作用：* 只有人类拥有行业Know-how，知道什么是“好结果”。
- **AI三角（Artificial Intelligence）：** 负责**场景、数据、基本功**。

  - *作用：* AI是外挂驱动器和效能放大器，负责处理海量信息和执行。
- **协同本质：** 不是“替代”，而是“互补”。

  - *模式：* 数据输入 -> AI处理 -> **人类校准（注入审美）** -> AI迭代。
  - *目标：* 认知共升，从“人力配合”升级到“碳硅协作”。

# 第一部分：项目管理与团队协作（落地五维度）

### 1. 明确定位：做减法

- **垂直聚焦：** 不做“全能AI”，聚焦“AI+金融理财”垂直场景。
- **核心痛点：** 放弃高难度的“预测未来”，专注解决**“数据整合-逻辑拆解-报告生成”** 的繁琐工作，把人从数据中解放出来做决策。

### 2. 科学管理：跨域协作

- **角色分工：** 金融老兵（审美）+ 技术极客（实现）+ 产品达人（体验）。
- **协作机制：**

  - *流程化：* 飞书文档分配任务，权责分明。
  - *双常态化：* 周例会（同步进度） + **智能体之夜**（纯AI技术与业务痛点碰撞，拉齐认知）。

### 3. 提升审美：拒绝拿来主义

- **调研方法：** 调研118项产品（Alpha派、东方财富等）。

  - *方法论：* AI筛选清单 -> 人工肉身试用（体感很重要） -> 拆解优劣。
- **审美标准：** 确定了“Alpha派的框架逻辑”+“东方财富的数据深度”+“全透明实盘演练”的差异化路线。

### 4. 建模革新：从“面向过程”到“面向人”

- **旧模式（IT思维）：** 死板的接口、固定流程，导致AI输出机械。
- **新模式（AI思维）：** 把AI当做**“团队成员”** 。

  - *指令方式：* 明确角色（资深分析师）、目标（核心摘要）、要求（逻辑/风险提示），而非死板代码。

### 5. 认知拉齐：从会用到懂行

- **去魅与赋能：** 培训团队理解Transformer原理、幻觉来源、Prompt结构。
- **Prompt公式：** **角色设定 + 任务描述 + 输出要求 + 反馈校准**。

# 第二部分：业务实战——“审美注入”方法论（孙杨军）

**核心痛点：** AI写不出“人话”，容易产生逻辑断层、废话连篇、一本正经胡说八道。

**解决方案：** **审美前置，分而治之**。

### 1. 行业分析：策略分析器（给AI戴上“有色眼镜”）

- **问题：** 混淆不同行业的分析逻辑（如用科技股逻辑分析银行股）。
- **手段：**

  - **第一步：强制归类。** 将31个行业强制归为4大类（金融地产、消费医药、科技成长、周期制造）。
  - **第二步：注入排他性关注点（Prompt审美注入）。**

    - *金融地产：* 关注股息率、监管、资产负债表。
    - *科技成长：* 关注TAM（市场空间）、摩尔定律、国产替代。
  - **第三步：Workflow逻辑锁定。** AI识别行业后，**只能**调用该行业对应的词汇库和逻辑，杜绝“串味”。

### 2. 估值分析：动静分离与风格选择（解决“数学造假”）

- **数据分类策略：**

  - **相对静态数据（Excel/知识库）：** EPS预测、CAGR、ROE预测。由人工定期更新，AI直接查表（快且准）。
  - **纯动态数据（API/插件）：** 股价、PE/PB。必须联网实时获取。
- **估值模型策略（风格分类估值法）：**

  - **拒绝问答题，做选择题：** 不让AI自己算DCF（太复杂不可控）。
  - **流程：** AI判断公司风格 -> 强制套用唯一公式 -> 填空计算。

    - *成长型：* 强制用PEG法（EPS × 增速）。
    - *价值型：* 强制用PB-ROE法。
    - *混合型/无评级：* 对应特定公式。

### 3. 迭代优化：降本提速

- **假设与验证：**

  - *知识库召回：* Top3 -> Top1（准确率未降，速度大幅提升）。
  - *去除冗余：* 删掉每个小节点的“润色”步骤，最后统一润色。
  - *节点合并：* 将盈利预测和估值分析“2合1”，利用上下文连贯性，省Token且逻辑更通顺。
- **成果：** 生成时间 2:40 -> 2:10；消耗Token 10万 -> 9万。

# 第三部分：技术破局——死磕100%数据准确率（张晓冬）

**核心痛点：** 金融容错率为0。Coze RAG（检索增强生成）是基于语义相似度的“图书馆翻书”（模糊/概率），而金融需要“财务室查账”（精准/确定）。

### 1. 平台与工具选型思考

- **对比：** Gemini/StepFun（长文本+代码解释器）像“查账”，能通过Python代码精准提取数据（`df['code']=='000861'`），准确度极高。
- **Coze现状：** 当时选型为Coze，需解决其数据库行数限制（实测>1000条难导入）和主键格式问题（0开头的股票代码变int）。
- **决策：** 弃用Coze内置数据库，采用**知识库+独立节点检索**方案。

### 2. 知识库检索的“灰盒陷阱”

- **问题：** 即使调整分片大小，全库盲搜仍会召回大量干扰项（如100个姓李的基金经理）。
- **定位：** 知识库只做“第一级粗筛索引”（从大海捞针到面盆抓鱼）。

### 3. 破局方案：工业级“三层锁定”机制

为了在Coze中实现100%准确，设计了特殊的Workflow节点逻辑：

- **第一层：身份锁定 (Identity Locking)**

  - **逻辑：** 提取唯一标识。用户输入“分析基金100060” -> 提取ID `100060`。
  - *细节：* 必须拿到标准ID才进入下一级，如果只有名称，先查表映射成ID。
- **第二层：暴力补全 (Universal Backfill)**

  - **逻辑：** 检查关键字段（基金经理、公司）。如果为空，**强制**启动搜索或查表。
  - *手段：* 构建“元数据”变量。比如没查到基金经理，就强制调用SearchTool去搜“XX基金的现任经理”，断绝AI瞎编的后路。
- **第三层：最终审计 (Final Audit)**

  - **逻辑：** 设立独立的LLM节点做“审计员”。
  - *Prompt规则：* 核对检索回来的JSON数据与用户请求是否完全匹配。例如：“如果召回片段中没有‘朱少醒’，直接忽略，不要强行关联”。

### 4. 最终架构选择

- **弃用：** 简单的“挂载知识库”模式（太黑盒，概率性生成）。
- **采用：** **独立节点检索模式 + 代码逻辑判断**（确定性生成）。

# 总结：AI落地的金句心法

1. **关于AI角色：** AI不是神，它是读过很多书但没有社会经验的学生。你不告诉它什么是好，它就给你“平均水平”（在金融界=垃圾）。
2. **关于准确率：** 追求100%准确率是有代价的（Token成本增加、响应变慢），商业化时需权衡，但金融场景必须死磕。
3. **关于核心竞争力：**

   - **技术决定下限**（工具会越来越强，Coze/Gemini/VibeCoding）。
   - **业务审美决定上限**（人类的Know-how、框架拆解、逻辑注入）。
4. **关于数据处理：** 语义检索是“模糊的艺术”，金融数据需要“确定的科学”。不能迷信RAG，必须引入“白盒化”干预。
