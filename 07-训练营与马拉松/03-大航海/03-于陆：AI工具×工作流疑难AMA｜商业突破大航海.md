**整体回答**

> 工作流和记忆这两件事，根因都是**显性化不足**——人脑里的判断逻辑没搬到配置里，模型只能猜。
>
> - **流程显性化**：每个 skill 的 `SKILL.md` 里把 trigger / skip 条件写死，"模糊地相关"也要 skip；description 要精确到"什么时候用、什么时候不用"。
> - **避免自由发挥（Q7）**：高风险步骤前强制开 plan mode；CLAUDE.md 里写「未确认前不修改关键文件」；把每次的"自由发挥"反例存到 feedback memory，下次自动规避。事后补救永远是被动的，**事前约束才是主动**。
> - **记忆管理**：MEMORY.md 只做索引（一行一条 ≤150 字符），具体记忆按 user / feedback / project / reference 四类拆到独立 md，互相 `link`。语义化分组比时间线分组好维护得多。
> - **判断幻觉/编造（Q27）**：要求引用具体文件路径+行号；对"功能曾经存在/已被移除"的历史性问题，让龙虾先 grep 验证再回答。
> - **单一龙虾边界（Q29）**：**走专业方向**，养多只专业龙虾，共享一个 skill 库；通用龙虾的稳定性会被无关上下文拖垮。
> - **Coze 钉钉/企微语音（Q22）**：是企业应用层拦截了 ASR，不是 Coze 的问题；在企业自建应用里接百度/讯飞 ASR 后转文本调 Coze。
> - 旧 Windows 跑 OpenClaw：开 WSL2，别用 cmd。
> - **Q13 飞书读取报错**：是 Qclaw 平台的飞书集成 token 过期或权限范围不全。重新授权时勾上"文档读写"+"知识库"两个 scope；龙虾报"APP 调不了"通常就是 OAuth scope 不够。
> - **Q15 多龙虾群聊**：群聊里"被 @"需要每只龙虾各自开 listener；龙虾间通信目前要靠共享文件夹或 IM 桥接（Truman IM 是首选）。
> - **Q26 Hermes 自动迭代 Skill 原理**：把"使用过程的纠错动作"（用户改了 prompt 或追加了规则）自动写回 SKILL.md，类似 RLHF 但用编辑距离对比人改前后。MVP 由首次能跑通的版本作为基线，之后只往这个基线上 patch。
> - **Q38 工具表格知识图谱 + 孩子学 AI**：可以用 graphify skill 跑一个工具图谱。孩子初中三类需求建议：**创意类**用即梦/Krea；**编程类**从 Scratch + Python 起步、配 Claude 答疑；**机器人控制器**用 micro:bit / Arduino 套件 + AI 辅助。

龙虾（OpenClaw）和记忆管理确实是两个相互交织的难点。核心问题在于：AI Agent 的"记忆"不是真正的记忆，而是上下文重载——每次对话都是独立会话，需要通过 Skill、MD 文件、变量传递等方式显式传递状态。

1. **分层记忆策略**：

   - 短期记忆：当前对话内的上下文（交给 AI 自动处理）
   - 中期记忆：MD 格式的工作文档（Obsidian/飞书文档，每次会话手动加载）
   - 长期记忆：结构化的配置文件（Skill、System Prompt）
2. **龙虾控制技巧**：

   - 用明确的文件路径指令替代模糊的文件名引用
   - 关键文件内容在 Skill 开头显式声明
   - 重要规则写入「工作协议」MD，每次会话先读
   - 验证 AI 是否真的读取：用「请复述你刚才读到的内容」来确认
3. **Windows 兼容性**：老电脑用 OpenClaw，建议用 WSL2 或 Docker 容器化部署，减少本地环境依赖。

## Skill全生命周期管理

**Q3：** 想要解决一个新问题，如何快速找到合适的Skill？假设找不到，如何从零到一炼制最佳实践级Skill？假设我有提示词，如何将提示词转变为Skill？假设找到了但不符合要求，如何修改Skill来满足自身需求？假设这个问题是一个复杂的工作流，需要多个Skill配合，又该如何做？假设我有一套提示词，之前是人工介入，用大模型对话来完成工作流，如何将这套工作流变成Cluade Code 调用Skill的形式？

**Q32：** 我目前是用的Codex+Obsidian解决AI记忆问题，把记忆做成本地md文件放进Obsidian中，这样记忆是可控的（和AI对话觉得有用就让他总结对话内容写成md文档当做记忆，不满意还可以让AI修改）这种记忆和养龙虾的记忆有什么区别？优缺点是什么？

【互动🙋🏻】提这些问题的同学在现场吗，可以扣个666；其他同学对这个问题感兴趣的，可以扣个1

**整体回答 这个是对的**

五个子问题是一条流水线：**发现 → 评估 → 改造 → 自创 → 协同**。

- **找（Q3.1）**：marketplace → plugin 仓库 → 一堂社群 → 自己写。
- **从 0 到 1 炼制（Q3.2）**：把工作流先跑 3 次人工版，记录每步的输入/判断/输出，再让 CC 用 `/init-skill` 转成 SKILL.md 框架，最后手工细化触发条件和反例。**没跑过 3 次的工作流不要做成 skill**——会僵化。
- **提示词 → Skill（Q3.3）**：提示词是一段话，skill 是有结构的"程序"。拆四块：触发条件 / 上下文 / 执行步骤 / 产出格式。
- **改 Skill（Q3.4）**：先改 description（影响触发），再改 body（影响执行）；version 字段要更新，否则 cache 不刷新。
- **多 Skill 协作（Q3.5/Q3.6）**：写一个 orchestrator skill 用 Skill 工具串联，**不要把多个 skill 塞进一段长 prompt**——会脆。
- **Codex+Obsidian 记忆 vs 龙虾记忆（Q32）**：前者透明可控、需要纪律维护、容易过期；后者自动、易漂移、需要定期清理。**推荐组合**：Obsidian 存原始素材和深度笔记，龙虾 MEMORY.md 存指令性记忆（偏好、规则、决策）。两者职责不同，不冲突。

## AI短视频工作流

**Q4：** 我一直是短视频和直播，以前是短视频编导和拍剪为主，现在想用AI将卖货类的短视频直接用工作流做出来，给到提示词，就能流畅出需要的视频，请问怎样搭建这样的工作流？选择什么工具搭建这种工作流？coze还是龙虾还是codex\trae等？

**Q33：** 我提一个比较弱智的问题，就是帮助小白，把做好的视频每天按照固定的时间自动上传到指定视频号上去

【互动🙋🏻】提这些问题的同学在现场吗，可以扣个666；其他同学对这个问题感兴趣的，可以扣个1

整体回答

- **Q4 卖货短视频工作流**：拆 4 段——文案 / 画面 / 配音剪辑 / 发布。**Coze 适合可视化拼装，CC+龙虾适合脚本控制和批量**。推荐：CC + Skill 总控，子任务调即梦/可灵生视频，剪映 API 套模板，最后自动上传。Trae/Codex 在视频领域不是首选。
- **Q33 自动上传视频号**：浏览器自动化（playwright / CUA） + cron 定时；保留登录 cookie；视频号官方接口受限要扫码，建议每周手工刷一次 cookie。

短视频 AI 工作流的核心是「脚本 → 素材 → 成片」三段式流水线。

**推荐工具栈：**

- 脚本生成：ChatGPT / Claude / Kimi
- 素材获取：Pexels / Pixabay 免费素材库 API
- 视频生成：剪映（图文成片）、即梦、即创
- 自动发布：抖音开放平台 / 视频号 API（需申请）

**最小可行工作流：**

1. 脚本模板 → AI 批量生成脚本
2. 素材库（关键词 + AI 生图）→ 自动匹配
3. 剪映图文成片 → 一键生成
4. 定时发布工具 → 自动化排期
**平台自动发布**：目前视频号、抖音均支持开放平台 API，建议用 N8N 或 Coze 做调度层。

**Q30：** 工具分层使用，操作系统级/Agent 工具，Openhuman，

**Q31：** 我初始想法是Hermes agent和Openclaw融合在一起，正常使用hermesagent有遇到操作时让hermes调用openclaw来做电脑操作，最终是一个Tui的形态，怎么样完整的融合在一起，只能本地跑各自的后端gateway吗？稳定性有很大问题，经常gateway掉线重启

**整体回答**

做"龙虾军团"前先想清楚三件事：

1. **数据映射（Q10）**：每只龙虾的私有记忆 + 一个共享知识库（飞书/Obsidian/Notion）+ 唯一的人类决策者 ID。所有产出文件统一前缀（`项目代号-日期-作者-内容.md`），**别让 AI 随机命名**——这是 80% 的混乱根源。
2. **指挥链（Q11/Q31）**：1 个总指挥龙虾（CC 起的）+ N 个执行龙虾。**总指挥不干活，只拆解、分发、验收**。中央集权比扁平群聊更稳定。
3. **通信机制（Q15）**：Truman IM 是首选；没有的话用共享文件夹 + 文件名约定，每只龙虾监听自己的 inbox 目录。

具体：

- **Q9 多 YAI 保留基础信息**：把"基础信息"做成一个共享 skill（`my-context.skill.md`），每只 YAI 启动时强制 import。
- **Q15 四只龙虾不全回应**：检查每只龙虾的 listener 是否开着、是否被 @ 触发；webhook 配置错的话只有"在线"的会回。
- **Q28 蜂群技战术**：Hermes 在长链路上比 OpenClaw 稳（自动重试 + sub-agent），但黑盒；OpenClaw 需要手动拆任务但透明。**长任务选 Hermes，需要调试选 OpenClaw**。
- **Q30 工具分层（操作系统级）**：CUA / Openhuman 处于"能用但不稳"阶段，关键流程别上生产；当浏览器自动化备胎可以。
- **Q31 Hermes + OpenClaw 融合**：目前只能本地各跑 gateway，TUI 一体化还没有官方方案；稳定性问题是 gateway 心跳超时，写一个 supervisor 自动重启脚本能压住大部分掉线。

数字员工体系的核心是「分工 + 通信 + 总控」三要素。

**架构建议：**

```Plain Text
总控 Agent（Hermes/龙虾）
├── 专业 Agent 1（调研）
├── 专业 Agent 2（文案）
├── 专业 Agent 3（审核）
└── 执行 Agent（Claude Code/Codex）
```

**通信机制：**

## Harness/ACP权限控制

**Q5：** Harness挽具，怎么用？

整体回答

Harness 是 Claude Code 的承载层（CLI / IDE 插件 / 桌面应用），它控制 tool 调用权限和 hooks 执行。

实操：编辑 `~/.claude/settings.json`：

- **`permissions.allow`**：自动允许（如 `Read`, `Bash(ls:*)`, `Bash(git status:*)`）。
- **`permissions.deny`**：禁止（如 `Bash(rm -rf:*)`, `Bash(git push --force:*)`）。
- **`permissions.ask`**：每次问。
- **`hooks`**：在事件发生时自动跑命令（如 PreToolUse 拦截高风险操作）。

推荐：常用只读工具加 allowlist 减少打扰；破坏性操作加 deny。可以用内置的 **fewer-permission-prompts** skill 扫历史 transcript 自动生成 allowlist。ACP（Agent Control Protocol）是更高层的协议，目前 Harness 是事实标准。

Harness（ACP）的核心是「权限分层 + 操作审计」。

**最小配置：**

1. **操作权限**：读取 / 写入 / 执行 三级
2. **资源权限**：文件访问范围、知识库分区
3. **日志审计**：所有操作记录可追溯

建议先用 OpenClaw 内置的权限配置，熟悉后再迁移到 ACP。

**整体回答**

- **Q12 TOB 主观体系审美**：没有公开资料就只能内部沉淀——把每个项目的"客户业务方案"做成对标库（哪个客户喜欢什么、为什么被拒、修改了几版），让 AI 在你已有审美上**再加 10%**。**不指望 AI 超过你**，指望它批量复用你的最佳实践。审美需要人类反馈来锚定，没有 ground truth 的领域 AI 没办法自己拉高上限。

- **结构化数据**：JSON / YAML（机器友好）

## Coze/Dify平台集成

**Q22：** 用云端Coze搭建的Agent，通过公司自己的应用集成到钉钉、企业微信后，不能直接用语音输入，即使扣子编程时已配置成用户用语音输入也不行，只能使用手机自带的语音转文字功能。如何实现直接的语音输入？

**Q23：** 用龙虾训练工作流程，然后想让龙虾去dify进行搭建，但是现在使用的效果来看，龙虾搭建dify时，习惯使用Python进行交付，这样工作流基本就失去意义了，变成Python代码实现控制，有没有解法？

**Q24：** Cron定时任务：1、在claude模型下可以正常执行，但是切换到deepseek之后，定时任务有时不会被触发，什么原因？2、如果是deepseek之下设置的cron，无论怎么切换后台大模型，基本就不会出现问题，什么原因？

**整体回答**

三个都是云平台的"最后一公里"问题：

- **Q22 Coze 钉钉/企微语音**：企业自建应用层把语音输入拦截了，Coze 拿不到。需要在企业应用层先接百度/讯飞 ASR，转文本后再调 Coze。Coze 本身的语音配置只对其官方渠道（如自有 web）生效。
- **Q23 龙虾搭 Dify 偏好 Python**：Dify 的节点抽象不够全（条件分支、循环、变量传递都比较弱），龙虾就用 Python 节点强行补齐。**解法**：(a) 让龙虾输出 Dify YAML 而非 Python；(b) 工作流复杂就换 N8N（节点丰富 10 倍）；(c) 实在要用 Python 就只用在数据处理节点，业务流仍走 Dify 节点。
- **Q24 Cron + 后端模型切换**：DeepSeek 的 function calling 实现与 OpenAI 协议有差异，部分 tool schema 不被识别，**cron 触发的工具调用会被跳过**。建议 cron 任务固定用 Claude 或 GPT-4，别让用户运行时切换后端

Coze 和 Dify 是互补关系，不是替代关系：

| 维度 | Coze | Dify |
|-|-|-|
| 部署 | 云端优先 | 支持私有化 |
| 编程要求 | 低 | 中 |
| 定制化 | 受限 | 高度自由 |
| 稳定性 | 高 | 需自行维护 |

**整体回答**

- **Q3 何时换对话框**：经验法则——**任务切换、上下文超过 70%、AI 开始重复或混淆时换**。同一个 plan 内不切，跨 plan 必切。经营分析看板的场景：**改顶部筛选栏一个对话框，改模块 a 一个，改模块 b 一个，悬浮框联调再一个**——分得越细越稳。

- **Q19 龙虾不读文件**：见 G4-Q19。
- **Q23 Trae + 3 万文件 token 爆炸**：分析框架——

  1. **哪些文件被 grep/read**？开 verbose log 看。
  2. **上下文里有多少冗余**？同一文件被 read 多次说明缺索引。
  3. **skill 是否每次 reload 同样内容**？skill 里 hard-code 大段引用 = 烧 token。
- 解法：把高频文件压缩成索引（一行一文件 + 一句摘要），按需 grep 再 read。

**Obsidian 治理（Q17）专门说明**：2000 → 近万文件 + 分类漂移，是 AI 辅助知识库的典型病。规则层设计：

- **inbox 模式**：所有新文件先进 `00-inbox/`，每周人工归档一次（**不交给 AI**）。
- **分类有限**：8-12 个顶级分类封顶，**不再开新分类**——要么并入现有，要么进 `99-misc/`。
- **AI 只补充元数据**：打标签、提摘要、拆长文，**不让 AI 移动文件**。
- **季度 rebuild**：每季度跑 graphify 看分类漂移，手工合并/拆分。

上下文爆炸的根因是「AI 不擅长自我总结和抽象」。

**解决框架：**

| **问题类型** | **根因** | **解决方案** |
|-|-|-|
| **对话越来越慢** | 上下文太长 | 定期开新对话 |
| **AI 忘记早期要求** | 上下文漂移 | 开新对话时先加载 MD |
| **Token 爆炸** | 知识库太大 | RAG + 语义检索 |

**主动管理**：每次完成一个子任务 → 总结关键结论到 MD → 开新对话时先读 MD

## Agent效果与模型选择

**Q6：** agent是否好用，是跟这个agent里植入的大模型有很大关系吗？国外的大模型真的比国内的大模型好用很多倍吗？

**Q17：** 伟强：我用Obsidian+Syncthing在多设备管理知识库，同时用Claude Code批量做文档预处理——打标签、分类、拆分超长文档，get 笔记每日云同步下载等。但跑了2个多月后出现了大麻烦：文件从最初的2000 多膨胀到近万，分类逻辑随时间漂移，想问于陆老师，这种AI辅助知识库治理的工作流，规则层应该怎么设计才能避免越整理越乱？

**整体回答**

- **Q6 agent 效果 vs 模型**：**模型决定上限，prompt/skill 决定下限**。国外模型在 agent 任务上目前确实领先（function call 稳定、长上下文连贯），但中文场景 DeepSeek/Kimi 已经够用。**不要无脑追国外**——agent 任务首选 Claude，纯文本任务国内模型性价比更高。
- **Q17 上下文管理**：见 G5。

模型选择原则：

| **场景** | **推荐模型** | **理由** |
|-|-|-|
| **简单问答** | 国产免费模型 | 成本低 |
| **复杂推理** | Claude 3.5 / GPT-4o | 推理能力强 |
| **代码生成** | Claude Code | 代码专用优化 |
| **中文内容** | Kimi / DeepSeek | 中文理解好 |

**策略一 成本优化**：用小模型做筛选，大模型做执行。

**策略二 最佳质量**：用你能用得起最好的。

## 找技术人员落地工作流

**Q15：** 想把精力集中在自己擅长的事情上，而非从头去学ai、学龙虾学爱马仕。想请技术按我的需求搭建我自己的定制工作流，怎么判断找到的人靠不靠谱，或者到哪里去找这样的人会比较靠谱？

**整体回答**

判断"找的人"靠不靠谱，三个信号：

1. **能问清楚你的业务**——不靠谱的人只问技术细节。
2. **给得出 MVP 范围**——不靠谱的人想"全包"（=没想清楚）。
3. **愿意签验收标准**——不靠谱的人"只对代码负责"。

**找人渠道**：

- 一堂社群（同道中人，标准接近）；
- 即刻（独立开发者多，价格中等）；
- V2EX 招聘节点（工程师味重）；
- GitHub Trending 中文项目作者（最贵但最强）。

**自己不学就完全外包的风险**：维护、迭代、扩展全卡住。**最优路径**：自己学到能验收的程度（不一定能开发），外包做 MVP，再自己维护和迭代。

判断技术人员靠不靠谱的三个问题：

1. 「你之前做过类似的项目吗？」→ 看作品集
2. 「这个需求你预计怎么做？」→ 看思路是否清晰
3. 「遇到问题怎么办？」→ 看解决态度

**找人渠道**：

- 一堂同学推荐（最靠谱）
- 自由职业平台（Upwork/电鸭）→ 明确需求再找
- 技术社群（知识星球、微信群）
- 招聘网站（多聊几个你就知道了）

## 短视频与内容生产

**Q8：** 想借助AI来运营小红书，主要流程是选题、收集材料、加工、发布，想知道AI做出来的最佳实践是怎样的

**Q10：** 老师你好，现在 AI 时代来临了，我想通过 AI +智能体的辅助，能够让我每天完成一本经典书籍的阅读和前沿论文的阅读。我应该怎么搭建这个工作流，并且怎么样结合 obsidian 知识库把这个整套流程打通，从选书到读书到做笔记到复盘的这样的一个完整的路径？

**Q12：** 如何制作一个类似抖音上销售的那种一键成片的短视频生产智能体？

**Q19：** 我正在经营琴行，需借助AI工具或搭建工作流，快速制作歌曲简化版曲谱，用于教学和学员练习。我的具体卡点是：AI工具使用不畅，4小节曲谱成功率极低，整首制作成功率为0，成品错误多，不确定是工具选择不当还是未搭建好工作流。

**Q20：** 如何调教我的文案写作生成工具，具有我的写作风格？是不是要把我自己的文章喂给它，那怎么喂，怎么提示，才能尽快的具备风格？

**Q26：** 于老师，公众号自动编辑，排版，发文公众号草稿，我虽然按照Noah的方法搭建成功了。但是我想自己搭建，采用自己的云函数（阿里云，腾讯云），这个云函数的设置，困扰我很久了，有没有不用云函数的方案？

**整体回答**

- **Q8 AI 运营小红书**：选题用 graphify 跑同类爆款找通用结构；材料用 Coze 工作流抓+清洗；加工用文案 skill 套你的风格；发布用浏览器自动化（注意防爬虫，G2-Q11）。
- **Q10 AI + Obsidian 每天一本书 + 论文**：**目标定太高**。建议每周一本深读 + 每天 30 min 论文摘要；AI 做"摘要+发问"，深读仍要你自己。Karpathy 的思路对（见 G5-Q24），落地有坑。
- **Q12 一键成片短视频**：抖音的产品本质是"脚本→素材→剪辑"三段套模板。自己做用即梦 + 剪映 API + Coze 编排，能做到 70% 自动化。
- **Q19 琴行简化曲谱**：4 小节成功率低、整首 0%，是因为视觉模型对乐谱不熟。**用 MusicXML 中间表示**——让模型生成 XML（结构化谱面），再用 MuseScore 转图。直接生成图永远不稳。
- **Q20 文案风格调教**：**别 fine-tune**——成本高、效果不一定好。喂自己 50 篇文章做 few-shot prompt 性价比高 10 倍。做一个 "我的写作风格" skill，里面 5-10 篇代表作 + 风格描述。
- **Q26 公众号自动编辑云函数**：阿里云/腾讯云函数配置复杂，**换 Vercel / Cloudflare Workers**门槛低 10 倍；或者干脆本地 cron 跑，公众号 API 不需要常驻服务。

短视频 AI 工作流的最佳实践：

**小红书爆款笔记自动化**：

1. 爆款采集：N8N + RSS + 关键词筛选
2. 结构拆解：Claude 分析爆款元素
3. 二创生成：模板 + 变量替换
4. 发布管理：Coze 定时任务

**核心心法**：AI 是放大器，不是替代品。最终质量还是取决于人的审美和判断力。

## 数字员工与B端落地

**Q2：** 软件开发在这个整个项目的生命周期中，它只是其中的一环。现在AI出来了以后，很多人用Agent来编程。从这个产品的设计、需求的收集、整理、架构，开发，测试，上线等等，从开始的需求到最终的交付，整个链条里面与之前的范式有什么不同？有没有可能做到前期搭好Agent后，只跟AI聊需求，剩下的事情全部AI来干？

**Q7：** 我一直在深耕在物流/供应链物流行业，针对B端这种复杂流程性场景，怎么把AI和具体应用场景结合，或者怎么找一个切入口把AI应用落地。有没有固定的套路？

**Q14：** 我是黄育成，我想用AI来赋能B端团队，提升营销能力，应该怎么实现最高价值环节的筛选和最小闭环的搭建。

**Q15：** AI怎么赋能智能硬件产品开发，辅助设计主板、编写硬件芯片？让普通人也能制造硬件原型吗？

**Q16：** 1、有一些建议是要用最好的产品，和最好的模型，比如 需要使用 anthropic 最好的模型，或者openai最好的模型，而不是国内的模型，你怎么看？2、如何定义ai原生的组织，每月token消耗成本高于人工？

**整体回答**

- **Q2 软件开发全链条 AI**：目前 **60% 自动化可达**（需求→设计→代码→测试），但 PM 角色（需求挖掘、优先级判断、客户沟通）不能完全替代。**agentic 开发的关键是测试自动化**——没有自动测试，AI 改完代码你不敢上线。
- **Q7 物流 / 供应链 B 端切入**：先做"单据处理"（OCR + 结构化），**ROI 最快、风险最低**；再做"异常预警"（数据分析）；最后才碰决策类（路径优化、库存）。**别上来就做决策类**——B 端容错率低，AI 不稳定客户会跑。
- **Q14 黄育成 B 端营销最高价值环节**：**客户画像 + 内容自动化是 80/20 处**。先做客户画像（结构化客户特征）再做个性化内容批量生成。最小闭环：1 个画像维度 × 1 类内容 × 1 个客户群。
- **Q15 AI 硬件开发**：辅助设计**可以**（KiCad + AI 推荐元件、PCB 布线建议），主板编程目前 AI 还不靠谱——**寄存器配置、时序、中断都容易出错**，需要工程师把关。普通人做硬件原型，**软件层 AI 帮 80%，硬件层 AI 帮 20%**。
- **Q16 国外 vs 国内模型 + AI 原生组织**：

  - **(1)** 是否一定用国外最好模型？**Agent 任务首选 Claude/GPT-4，纯文本任务国内模型够用**。盲目追"最贵=最好"是浪费。
  - **(2)** AI 原生组织 = **每月 token 消耗成本高于人工**？指标对，但本质是**人均产出（不是人头数）由 AI 决定**——5 人公司一年产出过去 50 人的量，那就是 AI 原生。

B 端 AI 落地的固定套路：

1. **选切入点**：选「人力密集 + 标准化程度高」的场景（如客服、报表）
2. **找最小闭环**：先让一个场景完全跑通
3. **评估 ROI**：投入产出比 > 3 再扩展
4. **沉淀最佳实践**：形成 Skill/工作流模板

**行业Know-How**：B 端的核心壁垒是行业经验，不是技术。用 AI 放大行业经验，而不是让 AI 从零学行业。

## 方法论驱动的智能体

**Q3：** 目前的需求是：在过去经验中积累了一些方法论，想做基于某个方法论，可以比较好地支持具体场景做决策/探索的智能体。之前试过用"扣子的知识库和工作流"来做，但出来的结果并不理想，很笼统，只是像个字典。目前视野中最佳实践就是YAI，我想了解YAI是如何做出来的？

**Q4：** 我是做老板IP孵化，后期是一个比较重的交付，想让AI工作流把账号定位、选题和文案脚本都搞定，不知道技术上能否实现，怎样搭建这样的AI工具或者智能体或者工作流？

**Q13：** 我是雪松，我想做一个训练虾，我想问一下你们是怎么做的？1. 底层能力：它首先具备调研能力，能够去市面上调研很多岗位的对标实践（Best Practice）。2. 信息转化：把这些对标实践写成 JD 或者其他形式。3. 配置写入：通过写入 OpenClaw 或者 Hermes 的配置文件的方式，把这些信息整合进去。

**Q17：** 1. 我做动漫周边海外跨境电商，日常需要批量做海外圈层文案、多语种产品话术、不同国家 ACG 用户偏好内容，如何设定结构化指令，让 AI 精准区分欧美、东南亚二次元圈层文化差异？

2. 一人战队做跨境轻资产项目，想借助 AI 完成选品推演、定价测算、转化链路设计，怎么把一堂的单元商业模型、ROI 三维决策模型高效植入 AI 对话？

3. 想要把 AI 深度融入跨境全流程（选品 - 文案 - 引流 - 复盘），对于一人创业者而言，优先打通哪一个环节的 AI 落地性价比最高？

**整体回答**

- **Q3 方法论智能体（YAI）做出来不是"知识库 + 工作流"那么简单**：核心是\*\*"决策树 + 反例库 + 自我纠错"\*\*三件套。

  - 决策树：你在什么场景说什么、为什么；
  - 反例库：哪些回答会被你否决、为什么否；
  - 自我纠错：每次输出后跟你的标杆对比，差距记下来下次避免。
  - Coze 知识库做不出来，是因为只有"对答库"没有"反例库"。

- **Q4 老板 IP 孵化**：账号定位/选题/脚本 **70% 自动化**；剩下 30%（人设、口播节奏、临场反应）仍要人。技术上：账号定位用 graphify 分析对标账号、选题用爆款拆解 skill、脚本用风格 skill。

- **Q13 雪松训练虾（调研→JD→写入配置）**：

  - **底层调研**用 web search + 浏览器自动化 + Quora/Reddit/招聘网站；
  - **信息转化**让 CC 把 BP 拆成 SKILL.md 框架；
  - **配置写入**自动化提交到 `~/.claude/skills/` 目录，git track。
  - **挑战**：BP 之间有矛盾（不同来源说法不一），需要人工做"取舍 layer"。

- **Q17 跨境电商动漫文化差异 + ROI 模型**：

  - **(1)** 文化差异用知识库 + 多语种 + 文化标签：欧美/东南亚的 ACG 偏好做成结构化 prompt 模板。
  - **(2)** 单元商业模型/ROI 三维**嵌入 prompt 而非依赖 AI 自己算**——AI 算数会错，但用 AI 调结构化公式很稳。
  - **(3)** 优先打通的环节：**文案** ROI 最高（成本低、批量大）；选品和复盘短期 ROI 低但长期价值大。

方法论智能体的核心是「把隐性经验显性化」。

**普通人怎么做**：

1. 整理自己的决策日志
2. 抽象为「如果...那么...」的规则
3. 用 Coze/Dify 实现为工作流
4. 不断用实际结果修正规则

## IP孵化与内容获客

**Q5：** 我是做教练的，在现有业务流中，有内容输出获客、客户档案管理、教练精进，在这个业务流中，AI能怎么帮到我？

**Q25：** 于陆老师好，我的场景和卡点是：

1. 社群管理：我想搭建一个同频者社群，让大家可以提出问题、相互交流，我会在里面定期做答疑。但社群运营对我来说比较难。我希望能够高效地运营社群、管理其中的信息。

2. 内容创作：我现在要做个人IP，需要多平台输出内容，包括朋友圈、公众号和小红书。不知道哪个大模型最好用？豆包。

**整体回答**

- **Q5 教练业务 AI + 信息安全**：

  - 内容获客 70% 可自动化（选题、初稿、排版）；
  - 客户档案**不要上云**——本地 SQLite + 本地 LLM（Llama/Qwen 本地版），完全离线；
  - 教练精进可以用 AI 模拟督导（虚拟咨询场景）。
  - **泄密风险排序**：Coze（云）> Claude/GPT（云但有企业协议）> 本地龙虾 + 本地模型（最安全）。
- **Q9 Quora 等社交媒体回答**：**完全可以自动化**——执行标准明确、批量大、容错率不低。流程：浏览器自动化抓问题 → 按业务相关度筛选 → CC 写回答 → 人工 review 5 秒 → 发。**人工 review 不能省**——AI 回答偶尔会跑偏。
- **Q18 跨境电商动漫**：见 G3。
- **Q21 健康行业 + 传统文化 IP**：把方法论沉淀成 skill，AI 当**对话伙伴**而非**权威**。信任来自**一致性**（你的内容风格稳定），不是 AI 的"高级感"。
- **Q25 社群管理 + 多平台内容**：

  - 社群运营用 Coze bot 做 **80% 答疑**（FAQ 类）；20% 复杂问题人工回（信任靠这 20%）；
  - 多平台内容用 graphify 找通用结构，再分平台 prompt 改写（朋友圈短、公众号长、小红书图文）；
  - **大模型选**：**Claude 写长文**，**豆包/Kimi 写社交内容**，**GPT-4 改写**——别强求一个模型干所有活。

AI 赋能 IP 的三层模型：

| **层级** | **AI 作用** | **人的价值** |
|-|-|-|
| **选题** | 数据分析 | 洞察判断 |
| **内容** | 初稿生成 | 风格打磨 |
| **互动** | 数据统计 | 情感连接 |

**整体回答**

- **Q3 垂直 Agent / Skill 变现**：三条路——

  - **(a) 卖订阅 SaaS**：把 Agent 包装成 web 产品收月费（如 5-50/月）；

- **Q25 企业 AI 产品形态**：主流四类——

  - **AI 客服**（QA 类、最成熟）；
  - **AI 内容生产**（营销、文案）；
  - **AI 数据分析**（结构化数据洞察）；
  - **AI Agent 平台**（流程自动化）。

1. **这是商业问题，不是AI问题**。想好你的需求，你只是提供了一个解决方案。
2. **练五步法**。需求验证比产品打磨重要。
3. **分析行业**。去预判一下整个行业的未来。不要只看眼前的产品，要看趋势。

AI 产品化的三条路：

| **路径** | **投入** | **适合人群** |
|-|-|-|
| **技能服务** | 低 | 个人开发者 |
| **SaaS 产品** | 中 | 创业团队 |
| **定制开发** | 高 | 企业服务 |

**垂直 Agent 的关键**：不是技术，而是行业深度。技术壁垒是暂时的，行业 Know-How 是长期的。

# 各方向总结

全部讲完了。我们快速回顾一下。

AMA从"怎么开始学 AI"开始，一路走到"在 AI 时代怎么找到自己的不可替代性"。五个方向，由浅入深。

**第一个方向，学习路径**。核心就一句话：**不要系统学习，先解决一个真实问题。** 从复刻项目开始，从第一场景开始。FOMO 是正常的，但不要让 FOMO 变成决策瘫痪。选一个工具，做一个场景，跑通再说。

**第二个方向，工具使用**。核心也是一句话：**工具不重要，场景和练习才重要。** 龙虾、Skill、Harness，这些都是你的武器，但武器好不好用，取决于你的基本功。忘掉别人的最佳实践，从自己的场景里长出你自己的 Skill。注意安全，第三方 Skill 要审查。

**第三个方向，工作流搭建**。核心：**Vibe Coding 有两种模式，用双三角来理解。** 口喷式适合探索，规划式适合落地。复杂项目从需求文档开始，拆分开来干活。国内模型不差，DeepSeek 调参也能完美解决问题。

**第四个方向，赋能场景**。核心：**从真实数据里找场景，从第一个闭环开始。** 不管是数字员工、老板 IP、教练业务还是物流供应链，找场景的方法是一样的——画流程图、标痛点密度、选数据就绪度最高的环节先做。安全方面，脱敏优于换工具。

**第五个方向，个人定位**。核心：**从人生红点到双三角模型。** 不要问"AI 会不会替代我"，问"我的双三角缺哪个角，AI 能不能帮我补上"。AI 做你的手，你做 AI 的脑。深耕 AI 做不到的部分——共情、直觉、信任、独特的判断。
