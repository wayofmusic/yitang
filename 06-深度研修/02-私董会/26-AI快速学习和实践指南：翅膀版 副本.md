# AI快速学习和实践指南：翅膀版 副本

> 大家好，我是翅膀。
>
> 这份指南不仅仅是三个月“大航海”的作业复盘，更是我从下载使用AI IDE开始，0帧起手总结出的一套“野路子”心法。
>
> 如果你也想从“不敢写代码”到“亲手部署自己的应用”，那这份指南也许能给你一点启发。
> PS：为精简篇幅，部分不懂的词汇请AI First——问豆包。

## Part1：认知重构——定义“航海”坐标

### 1. 核心路径

- **专注领域**：**AI编程（Vibe Coding）** 与 **AI视频**。

  - 关于AI编程：有没有一件事，即便不赚钱你也想去做？对我来说，就是打造一件自己想要的产品。于是，AI编程理所当然的成为我一个必须学会的技能。
  - 关于AI视频：AI生视频是本次大航海想锻炼的能力之一，从生图生视频的提示词练习，到子弹库的积累，再到手动工作流的打造，最终来到自动化工作流的追求——不可避免的，能力需求来到了AI编程上。
- **本质认知**：

  - **编程定义的重构**：在AI时代，编程不再是学习复杂的语法和数据结构，而是**用自然语言与AI对话**。
  - **元能力**：掌握了这种“自然语言编程”能力，就拥有了“泛产品设计”的能力。以前需要整个团队（前端、后端、设计）做的事，现在一个人+AI就能闭环。
- **AI编程提升路径**

  1. **提示词**：踏入AI之门的第一个技能，也是贯穿之后**智能体**、**多模态**、**AI编程**的打底技能。
  2. **Agent**：通过对智能体的使用，来深入理解智能体的边界与机制，当编程中使用到AI模块时，这将是绕不过的一环。
  3. **多模态**：AI文本、AI生图、AI视频、AI语音、AI音乐多模态混合调用，涉及的工具上上手、玩一玩，将加深在“泛产品设计”时的规划与落地能力。
  4. **AI编程** = 泛产品设计能力 + 提示词能力 + 产品理解能力（含AI多模态） + 技术构建能力（含Agent架构理解）

  - PS：如果要编程打造的产品不包含AI模块，则不需要多模态和Agent架构的理解。

### 2. 思维模式升级：从“工具控”到“AI First”

- **Before**：遇到问题先搜索，或者问问万能的朋友圈，最后才想起来问AI。
- **After（AI First思维）**：将AI作为第一思考伙伴，并建立了明确的**三个边界**（范式洞察）：

      1.  **问AI**：快速建立理解框架、执行具体代码、获取外部信息。

      2.  **自己学**：领域基础知识、价值判断与决策、系统性思维构建。

      3.  **要存档**：重要的思考洞察、技术文档、可复用的Prompt流程、成型的知识体系。

## Part2：成长心法——IPO螺旋与刻意练习的融合

### 1. 方法论提升：IPO螺旋迭代 + 刻意练习

**认知重构**：本次大航海中，我将个人成长的底层逻辑，总结为「IPO螺旋迭代 + 刻意练习」的深度融合。

#### 1.1 旧范式 vs 新范式

- **传统 IPO (Input-Process-Output)**：

  - **Input**：读书、看课。
  - **Process**：大脑记忆、笔记整理（耗时最长）。
  - **Output**：知识点、思维导图。
  - **痛点**：Process 环节效率低，Output 往往停留在"知道"层面，难以转化为"做到"。
- **AI 时代的 IPO**：

  - **Input (最佳实践)**：AI 辅助快速检索全球最佳实践，作为高起点的输入。
  - **Process (AI 全面赋能)**：**这是最大的变量**。将 Process 环节外包给 AI（如 Vibe Coding、AI 写作），人类从"执行者"升级为"指挥官"（定义、约束、审美）。
  - **Output (产品化)**：产出不再限于笔记，而是**可运行的代码、可发布的视频、可使用的工具**。
  - **Iteration (螺旋迭代)**：每一个 Output 都成为下一个循环的 Input，形成复利。
- **警惕**：分清自身要掌握的能力与借助AI生长出来的能力，避免丧失主动性而被AI裹挟。

#### 1.2 「IPO + 刻意练习」执行路径

**Step1：Input - 锁定「最佳实践」**

- **原则**：不要闭门造车，先找最佳实践刷审美。
- **路径**：传统搜索 + 专用AI检索工具 + 训练大数据。
- **行动**：

  - 主动搜索：边学边干，碰到不懂的：AI Frist > 传统搜索 > 咨询高手。
  - 被动推流：利用大数据，在视频号/B站/Youtube常点击想要内容类型，第2天就会主动推送给你。
  - 积累子弹库（如用 Eagle 建立视频/图片池，用Notion/飞书 建立图文知识库）。
- *个人案例*：在做短视频时，积累"子弹库"（提示词模板、音效库），这是对自身最佳实践的封装。

**Step2：Process - 建立「标准化 SOP」**

- **原则**：将隐性知识显性化，将显性知识流程化。
- **路径**：人类把控方向 + Embeding AI执行。
- **行动**：

  - **SOP 固化**：制定工作流（Workflow），让AI参与Input到Output的转化。
  - **结构化约束**：给AI设定"人设"和"规则"（即"对AI的刻意练习"）。
- *个人案例*：在Claude Code中，我不再只是用AI IDE来写代码，而是设计Workflow，让AI完成信息收集 → 处理 → 输出的全过程。（[翅膀：🤖我用AI搭建「一页纸」的workflow](https://www.feishu.cn/docx/LEAdd103uoI1HdxkANCcxMQXnJc)</cite>）

**Step3：Output - 跨越舒适区的「产品交付」**

- **原则**：以"作品"为导向，而非以"学习"为导向。
- **路径**：边学边做 + AI做放大器
- **行动**：

  - **最小可行性产品 (MVP)**：每次练习都要有一个具体的产出物（APP、插件、视频）。
  - **难度动态提升**：简单的 Python/JavaScript/AutoHotKey 脚本 -> CLI工具 -> 本地 GUI 工具 -> Web 端部署 -> 商业化 Demo。通过不断提高 Output 的标准，让自己在 Process 环节升级认知。
- *个人案例*：从  [5️⃣翅膀：🔍用AI编程实现一键检索](https://www.feishu.cn/wiki/EmsrwEGc7it19FkwG3lczF08nyb)</cite> 到 [小说转漫剧Agent](https://novelcon.lucasicloud.xyz/)。

**Step4：Iteration - 螺旋迭代**

- **原则**：每次输出，都是为下一次输入攒牌。
- **行动**：每次交付后的复盘（攒牌），都会成为下一次开发的起点。
- *个人案例*：大航海作业本身就是一次次的迭代。第13周的思考成为第14周 VibeCoding范式的输入，前面每次作业，最终汇聚成本次的"一页纸"方法论。

### 2. 深度学习范式

- **以AI为师**：eg. 让ChatGPT引导Claude Code工作流的学习，边做边学，不仅仅停留在原理理解，也不仅仅停留在操作层面。
- **IPO螺旋**：Output（一页纸教程）倒逼Input（深入细节研究），形成正向循环。

## Part3：实战兵法——技术心法与工具组合拳

### 1. 核心技术心法

- **上下文工程（Context Engineering）**：

  - 深刻理解LLM没有“长时记忆”，对话的本质是**上下文管理**。
  - **实战技巧**：主动判断何时重启对话、通过输出文档减少当前窗口上下文、对话窗口记忆迁移、模块化管理不同窗口。
  - Eg. 《通用版上下文迁移提示词》

    ```YAML
    【上下文迁移 / 新窗口承接 Prompt】

    我判断当前对话的上下文可能已经接近或超过安全上限（token 过多 / 记忆开始混乱）。
    为避免信息丢失与质量下降，我希望你执行一次「上下文收束与迁移」。

    请严格按以下流程执行，不展开新的讨论内容：

    ---

    【步骤 1｜理解确认】
    - 简要确认你已理解：我们将把“接下来需要继续讨论的内容”，迁移到一个新的对话窗口中继续。
    - 若你认为当前无需额外澄清，可直接进入步骤 2。

    ---

    【步骤 2｜关键信息收束】
    请基于当前对话内容，提炼并输出：
    1. 当前讨论的【核心主题 / 目标】
    2. 已达成的【关键结论 / 共识 /已确认设定】
    3. 尚未完成、需要在新窗口继续的【下一阶段任务 / 问题】

    要求：
    - 高度概括
    - 不引入新观点
    - 不做延展性分析

    ---

    【步骤 3｜新窗口 Prompt 生成（核心输出）】
    请生成一段【可直接复制到新对话窗口使用的 Prompt】，用于让“新的你”快速进入状态。

    该 Prompt 需包含：
    - 明确的【角色设定 / 协作身份】
    - 当前所处的【讨论阶段 / 节点位置】
    - 新窗口需要继续处理的【具体任务说明】
    - 必要的【约束条件 / 输出要求 / 风格要求】

    格式清晰、结构化，避免冗余背景说明。

    ---

    【步骤 4｜长文与高价值内容处理（如适用）】
    如果你判断在当前对话中存在：
    - 篇幅较长
    - 逻辑复杂
    - 对后续讨论“不可忽略”的内容

    请：
    - 明确指出【建议打包为 .txt 文件的内容名称】
    - 简述该文件的【用途与在新窗口中的使用方式】
    - 不要在当前对话中重复输出全文

    ---

    【重要约束】
    - 不继续推进实际业务内容
    - 不进行创造性扩写
    - 你的最终输出 =「步骤 2 的总结」+「步骤 3 的新窗口 Prompt」
    - 语言清晰、中性、跨模型通用

    当你准备好后，请直接输出结果。
    ```
- **“子弹库”思维**：积累可复用的子弹，就是攒牌的方式之一
PS：封装就是将可复用的内容存档起来、方便调用，不是什么厉害的动作

  - 封装Prompt
  - 封装workflow

  - **项目解耦**：将项目拆成模块、原子化、最小单元化。
  - **AI执行解耦**：让AI将代码分模块单元写，避免后续bug。
  - Eg. AI代码解耦提示词

    ```Markdown
    2. 请将可解耦的功能模块图，写入RPD.md文件中。
    3. 请根据上述可解耦的功能模块，对代码进行解耦操作，使解耦后的代码将更易于拓展、优化。
    ```

### 2. 新的工作范式：Agent构建思路（黄金圈）

- **Why（目标层）**：先明确Agent要解决什么问题？再找AI讨论方案。（eg.写一个小脚本）。
- **How（方法层）**：

      \- **起手式**：从Plan做起（与AI讨论方案，讨论可行性，避免里程碑原点回退）。

      \- **LLM选择**：Claude Sonnet/Opus（编程强） vs Gemini Pro（上下文长）。

      \- **规划机制**：如何将任务拆解为Step-by-step的步骤。

      \- **工具调用**：赋予Agent搜索、读写文件的能力。

- **What（产出层）**：最终交付的产品形态（代码、文档、视频）。

### 3. 工具链：

- **【原型验证神器】Google AI Studio**：Token大方，语义理解精准，适合快速验证想法，跑通MVP。
- **【本地工程部署落地】Trae/Cursor/Antigravity**：任务式地调用Agent，本地编写更为灵活。
- **多Agent思路：**

      \- **调用解耦**：不同模块/不同项目/不同功能

      \- **记忆同步**：定期存档/分模块处理 → 进阶打造上下文自动化

      \- **版本存档**：定期Git版本管理，避免翻车

      \- **封装子弹**：常用workflow进行封装

      \- **提高视角**：用各种方法避免微观管理（想方设法交给AI），将AI当作岗位角色进行管理（eg.让AI管理AI），多注重宏观管理与思考。

## Part5：AI时代的人类定位

### 1. 人类的自我定位

- **人类审美 = 提出问题 x 自然语言交互 x 系统拆解**
- **拆解说明**：

  - **提出问题**：人来定义“What”和“Why”，AI来解决怎么做“How”。
  - **自然语言交互（Prompt）**：

    - 自然化、口语化，别让AI生成的Prompt带偏。
    - 核心不是背诵格式，而是“自然语言”与“精细Prompt”的切换。
    - 创造性任务用自然语言（不设限），工程性任务用精细Prompt（结构化、约束明确）。
  - **系统拆解与架构**：将问题拆解为可各司其职的原子节点 → 统筹组织Agent来解决问题。

### 2. AI时代的必备思维

- **泛产品设计思维**：用AI做放大器，新领域20h的投入不再只能达到60+分，而是能追求90+分。
- **资产思维**：沉淀下来的Prompt和Workflow才是时间的朋友。
- **AI x 人类 = 写轮眼**：洞察能力 & 分析能力 & 复制能力

  - 写轮眼是在AI加持下的一个进阶能力，就好像我看了这个APP的界面一眼，我就能复刻出来；我看了你展示的能力，那么你的能力不久后我就能学会了。是不是十分神奇？

### 3. 自驱与行动

- **做中学、学中做**：兴趣和AI都是你最好的老师，先追求完成，再追求完美。
- **相信AI做得到**：AI如果做不到，那必然是人类的审美问题。
- **不迷信AI**：不断锚定人与AI的边界，永远Embeding，而不是放手Agent。
