# 第一章：认知篇——先把脑子里的"墙"推倒

## 1.1 你不需要成为程序员

我先说一个反直觉的事实：

**学AI，不等于学编程。**

很多人一听到"AI编程"就退缩了，觉得那是程序员的事。但2025年之后，这个等式已经不成立了。

Andrej Karpathy（OpenAI创始成员、特斯拉前AI总监）在2025年2月提出了一个概念叫**Vibe Coding**——“氛围编程”。核心意思是：

> 你不需要写代码，你只需要用自然语言告诉AI你想要什么，AI来帮你实现。

就像你不需要会画画才能使用Midjourney生成图片，你也不需要会编程才能用Cursor、Lovable这些工具搭建网站和应用。

**你需要的是**：

- 清晰地描述你想要什么（需求定义）
- 学会和AI协作（人机协同）
- 能够验证AI做得对不对（质量把控）

这些能力，和你是不是程序员没有关系。

---

传统编程流程：

需求 → 学习语法 → 写代码 → 调试 → 部署

     （需要几个月到几年的学习时间）

Vibe Coding流程：

需求 → 用自然语言描述 → AI生成代码 → 验证结果 → 部署

     （从第一天就可以开始做项目）

---

## 1.2 Vibe Coding：AI时代的"识字能力"

我在"大航海"期间选择聚焦Vibe Coding，有一个很明确的判断：

**Vibe Coding就像AI时代的"识字能力"。**

你可以不当程序员，但你得能把一个想法做成一个别人能点开、能体验、能吐槽、能付费（至少能反馈）的东西。

不然就会长期停在一种状态：

“我有个点子”——“我也问过AI”——“然后呢？”

然后就没然后了。

Vibe Coding对我来说不是技术崇拜，它更像**一把扳手**：把AI的能力拧进现实世界。

想象一下，如果你能：

- 3分钟把一个想法变成一个网站
- 用AI帮你自动处理繁琐的工作
- 把你的知识做成产品，让更多人受益

这不是程序员的专利，这是每个人都可以拥有的能力。

## 1.3 打破三个致命误区

在开始学习之前，我想帮你打破三个最常见的误区：

### 误区1：“我得先学完理论，再开始实践”

**真相：实践是学习理论的最好方式。**

我见过太多人，买了一堆课程，收藏了无数教程，就是不开始。他们在等一个"准备好"的时刻。

但这个时刻永远不会来。

研究表明，项目制学习（Project-Based Learning）的效果远超传统学习方式。密歇根大学的研究发现，参与项目制学习的学生，在学业成绩、情感态度和思维能力上都显著优于传统课堂的学生。

**我的建议：边做边学。** 遇到不懂的概念，当场查；做出bug了，当场改。这种"即时反馈"的学习方式，比任何课程都有效。

### 误区2：“AI工具太多了，我不知道选哪个”

**真相：选择哪个工具不重要，重要的是开始用。**

2025年的AI工具生态确实很繁荣：Cursor、Claude Code、Gemini CLI、Lovable、Bolt、Windsurf……光看名字就头大。

但这就像问"我应该学哪种外语"一样——最好的答案是：**随便选一个，先用起来。**

工具之间的差异没你想象的那么大。当你真正开始用的时候，你自然会知道什么适合你、什么不适合你。

我后面会给你一份工具选择指南，但请记住：**工具是手段，不是目的。**

### 误区3：“我做的东西太简单了，不值得分享”

**真相：每个人的学习过程都有价值。**

你做的第一个网站可能很丑，你写的第一个教程可能很稚嫩，你开发的第一个工具可能只有你自己在用。

**But so what?**

我的第一个项目叫"3分钟用AI搞定全栈网站部署"，技术含量几乎为零。但它帮助了很多和我一样的非技术人士迈出第一步。

**做出来，就是胜利。**

不完美没关系。发布了，才能得到反馈；有了反馈，才能迭代；迭代多了，才会变好。

这就是成长的闭环。

# 第二章：方法篇——刻意练习的四个核心要素

## 2.1 为什么你的学习效率低？

我早期学习AI的方式很随意：今天想做什么就做什么，明天有兴趣了再继续。

结果呢？一年下来，感觉学了很多，但拿不出什么像样的作品。

直到我认真研究了一堂关于**刻意练习**（Deliberate Practice）的理论，才明白问题出在哪里。

心理学家安德斯·艾利克森（Anders Ericsson）研究了大量领域的顶尖高手——从国际象棋大师到小提琴演奏家，从外科医生到运动员。他发现了一个惊人的事实：

> **天才不是天生的，而是"练"出来的。**

但关键不在于练习的时间长短，而在于**练习的方式**。

艾利克森把练习分成三类：

1. **玩耍（Play）**：享受和探索，没有明确目标，比如随便弹弹吉他
2. **工作（Work）**：完成任务，但不刻意提升，比如每天重复做同样的事
3. **刻意练习（Deliberate Practice）**：有明确目标、即时反馈、走出舒适区的系统性训练

只有第三种——刻意练习——才能真正让你变强。

---

## 2.2 刻意练习的四个核心要素

基于艾利克森的研究，我总结出刻意练习的**四个核心要素**：

### 要素1：走出舒适区（Stretch Zone）

**【舒适区三层模型】**

│                                     │

└─────────────────────────────────────┘

真正的成长发生在不舒服的地方。

如果你做的事情太轻松，说明你在原地踏步。如果你做的事情太难，你会直接放弃。

**最佳学习区**是那个"有点难，但努努力能做到"的区域。

**实操建议**：

- 每个新项目，都比上一个稍微复杂一点
- 如果三天内就能做完，说明挑战不够
- 如果一个月还做不完，说明拆分不够细

### 要素2：即时反馈（Immediate Feedback）

没有反馈的练习是无效的。

你需要知道自己哪里做对了，哪里做错了，才能调整方向。

**在AI学习中，反馈来自哪里？**

1. **AI工具本身**：代码报错就是最直接的反馈
2. **真实用户**：把作品发出来，让别人用，听他们的吐槽
3. **社群同学**：找一群一起学习的人，互相review
4. **自己的复盘**：每个项目做完，写下什么做对了、什么做错了

**实操建议**：

- 每个项目完成后，写一份复盘（哪怕只有500字）
- 把作品发到群里或朋友圈，收集反馈
- 遇到bug不要急着问AI，先自己想10分钟

### 要素3：掌握套路（Mental Representations）

高手和新手的差别，不在于智商，而在于脑中的"模式库"。

象棋大师能在几秒内记住整个棋局，不是因为他们记忆力超群，而是因为他们识别出了**棋局的模式**。

同样，学习AI的过程，就是不断积累"套路"的过程：

- 这种类型的问题，应该怎么描述给AI？
- 这种类型的bug，通常是什么原因？
- 这种类型的项目，应该用什么技术栈？

**实操建议**：

- 每学到一个有效方法，就记录下来
- 建立自己的"prompt模板库"
- 把别人的最佳实践抄过来，先用，再理解

### 要素4：大量重复（Repetition）

没有捷径。

一万小时定律虽然被过度简化了，但其核心洞察是对的：**足够的练习量是必要条件**。

**实操建议**：j

- 给自己定一个可量化的目标，比如"每周完成一个项目"
- 不要追求完美，追求数量——质量会在数量中自然涌现
- 坚持记录，让自己看到进步

## 2.3 我的刻意练习计划

在"大航海"开始时，我给自己定了一个很硬的目标：

> **大航海期间（3个月），每周完成一个项目，并写复盘教程。**

这个目标符合刻意练习的四个要素：

1. **走出舒适区**：每个项目都比上一个稍微复杂
2. **即时反馈**：发布到社群，收集同学反馈
3. **掌握套路**：写教程的过程就是提炼套路的过程
4. **大量重复**：3个月20个项目，密度足够高

三个月下来的结果：

- ✅ 20个项目
- ✅ 19份教程
- ✅ 多个"从想法 → 上线 → 迭代"的完整闭环
- ✅ 从"会做网页"到"能做产品"的能力跃迁

**这不是天赋，这是方法。**

因为"发布"这个动作会产生巨大的心理变化。

一旦发布，它就变成了"公开的"、“可被评价的”、“真实存在的”。

**这个心理门槛，越早跨过越好。**

- 团队协作项目（和Git集成好）

### Claude Code：全能合伙人

**核心定位**：高度自主的"工作流引擎"

它像一个高度自主的"工作流引擎"。你给它一个复杂任务，比如"重构这个模块并修复测试"，它会自己思考、自己跑测试、自己修正。

**核心特点**：

1. **自定义能力强**：Hooks机制，可以在特定事件触发时执行自定义脚本
2. **能自我修正**：运行测试失败了，它会自己分析原因，修改代码，重新测试
3. **适合端到端的复杂任务**：从分析需求到写代码、测试、修复，一气呵成

**适用场景**：

- ✅ 项目级重构
- ✅ 自主调试（让它自己找bug、修bug、验证）
- ✅ 长会话的复杂开发
- ✅ 需要AI"自己搞定"的任务

**实操示例**：

# 安装 Claude Code

npm install -g @anthropic-ai/claude-code

# 在项目目录中启动

claude

# 给它一个任务

> 重构 src/utils 目录下的所有工具函数，添加 TypeScript 类型，并写单元测试

Claude Code会自己分析现有代码、制定重构计划、执行修改、运行测试、根据测试结果修正。

**优点**：

- 天花板最高：能完成最复杂的任务
- 高度自主：可以独立完成整个流程
- 可定制性强：Hooks机制让你控制每一步

**缺点**：

- 学习曲线陡：新手需要时间适应
- 需要一定基础：你得能看懂它生成的代码，验证结果

**王欢的评价**：

> “Claude Code是我用过的最聪明的AI编程工具。它不只是代码助手，更像是一个能独立思考的合伙人。”

### Gemini CLI：博学家

**核心定位**：超大上下文的"研究助理"

上下文窗口极大，能一次性消化海量代码和文档。可以把几百个文件同时吃进去分析。

**核心特点**：

1. **超大上下文窗口**：可以一次性处理几十万token，相当于几百个文件
2. **强大的信息整合能力**：能快速理解整个代码库的结构和逻辑
3. **与Google生态集成**：和Vertex AI、Google Cloud无缝衔接

**适用场景**：

- ✅ 大规模跨文件重构
- ✅ 基于外部文档编写代码（如API文档、设计文档）
- ✅ 需要理解整个代码库的任务
- ✅ 快速理解陌生项目

**实操场景**：

假设你接手了一个10万行代码的老项目，需要快速理解它的架构。

传统方式：一个文件一个文件看，可能需要一周。

用Gemini CLI：把所有核心文件喂给它，让它生成架构文档，可能只需要一小时。

**优点**：

- 上下文超大：能"看到"整个项目
- 理解能力强：擅长分析和总结
- 适合"看全局"的工作

**缺点**：

- 自主性中等：没有Claude Code那么自主
- 更偏分析：擅长理解而非执行

**王欢的评价**：

> “Gemini CLI像一个博览群书的研究助理。当你需要快速理解一个大型项目时，它的价值就体现出来了。”

### Codex CLI：严谨医生

**核心定位**：精准可控的"微创手术医生"

设计哲学是"每一步都清晰可控"。每一步操作都很精准，适合做"微创手术"。

**核心特点**：

1. **精准安全**：每一步都经过验证，不会"乱来"
2. **沙箱机制**：在安全环境中执行，不会破坏现有代码
3. **完全可控**：你可以查看并批准每一步操作

**适用场景**：

- ✅ 精准的代码修改（修改特定函数、优化特定逻辑）
- ✅ 需要完全掌控每步变更的场景
- ✅ 对代码质量要求极高的项目
- ✅ 保守型开发者

**优点**：

- 最安全：不会搞砸现有代码
- 最稳定：可预测性强
- 最可控：每一步都透明

## 4.6 Vibe Coding最佳实践：11条黄金法则

根据Zapier的研究和王欢的实践，总结出Vibe Coding的**11条黄金法则**：

### 法则1：不要期待魔法

很多人看到"一句话生成APP"的演示就兴奋了，以为AI真的能一步到位。

**真相是：复杂项目不可能一个prompt搞定。**

AI不会完全尊重你prompt中的每一个细节。你需要把大目标拆成小目标，逐步实现。

### 法则2：先写PRD

在动手写代码之前，先写一份**产品需求文档（PRD）**。

PRD应该包括：

- 产品描述：做什么？给谁用？
- 功能列表：哪些功能？优先级？
- 技术方案：用什么技术栈？
- 开发里程碑：分几个阶段？

**PRD不只是给AI看的，更是帮你理清思路的。**

### 法则3：先画线框图

在写代码之前，先把用户界面画出来。

不需要很精美，草图就行。目的是：

- 理清用户流程
- 发现逻辑漏洞
- 和AI沟通更高效

推荐工具：Excalidraw、Figma、甚至纸和笔。

### 法则4：用Git做版本控制

**这条非常重要。**

Vibe Coding的过程中，AI经常会改出问题。如果没有版本控制，你可能会丢失之前的工作。

每次AI改完代码，如果运行正常，立刻commit一次。

git add .

git commit -m "feat: 添加用户登录功能"

### 法则5：设置全局规则

每个Vibe Coding工具都支持"全局规则"或"系统提示词"。

利用这个功能，告诉AI：

- 你希望它扮演什么角色（比如"资深全栈工程师"）
- 你偏好的编程风格
- 你的项目约定（比如"使用TypeScript"）

### 法则6：先建数据库

如果你的项目需要存储数据（用户信息、内容数据等），**在开始写代码之前就把数据库设计好**。

王欢踩过的坑：先做功能，后加数据库，结果要改的地方太多，几乎重写。

推荐数据库：Supabase（免费额度大，和各种工具集成好）

### 法则7：一次只做一件事

这是最重要的法则之一。

**不要在一个prompt里塞多个需求。**

❌ 错误示范：

> “添加用户登录功能，同时优化首页样式，顺便修复那个按钮点击不了的bug”

✅ 正确示范：

> “添加用户登录功能。要求：1. 支持邮箱登录 2. 支持Google OAuth 3. 登录后跳转到首页”

### 法则8：验证后再接受

AI给出的代码，**不要盲目接受**。

在点击"Accept"之前：

- 读一遍代码，看有没有明显问题
- 运行一下，看功能是否正常
- 测试边界情况

AI会犯错。你需要做质量把关。

### 法则9：频繁测试

不要等所有功能都做完再测试。

**每做完一个小功能，就测试一下。**

测试的内容：

- 正常流程能跑通吗？
- 边界情况处理了吗？
- 错误情况有提示吗？

### 法则10：不要太执着于一个项目

Vibe Coding很容易上瘾。你可能会在一个问题上死磕好几天。

**如果一个方向试了很多次都不行，考虑换个思路，甚至重新开始。**

Andy Keil（Dreambase联合创始人）的建议：

> “不要害怕扔掉工作。如果你撞墙了，感觉在螺旋式下坠，拿着你学到的东西，重新开始。”

### 法则11：Just Start

最后一条，也是最重要的一条：

**别想太多，开始做。**

你可以忽略上面所有的建议，直接打开一个Vibe Coding工具，开始描述你想要的东西。

在做的过程中，你会自然学到该学的东西。

## 5.3 AI时代的核心竞争力公式

在AI时代，什么能力才是真正的核心竞争力？

很多人焦虑会被AI替代。王欢的答案是一个公式：

**【核心竞争力公式】**

---

### 维度1：问题定义力

**定义**：发现问题、定义问题、拆解问题的能力。

AI很擅长解决问题，但它**不擅长发现问题**。

能问出好问题的人，比能给出标准答案的人更有价值。

**怎么提升问题定义力？**

1. **多问"为什么"，追问到根本原因**
2. 不要停留在表面问题。用"5个为什么"方法深挖。
3. **示例**：
4. 问题：用户流失率高
为什么？→ 因为用户不活跃
为什么不活跃？→ 因为产品功能不够吸引人
为什么不够吸引人？→ 因为没有解决用户真正的痛点
为什么没解决痛点？→ 因为我们没有真正理解用户需求
为什么没理解？→ 因为我们没有做用户调研

真正的问题：缺少用户调研机制
5. **从用户视角思考，而不是从技术视角**
6. 不要问"我们能做什么技术"，而要问"用户需要什么"。
7. **学会拆解：大问题→中问题→小问题**
8. **示例**：
9. 大问题：提升团队效率
  ↓
中问题：减少重复性工作
  ↓
小问题：自动化周报生成

---

### 维度2：系统设计能力

**定义**：把复杂的事情拆解成模块，设计它们之间的关系，让整体运转起来。

AI擅长局部优化，但**不擅长整体设计**。

能做系统架构的人会越来越稀缺。

**怎么提升系统设计能力？**

1. **学习成熟系统的架构（开源项目、经典案例）**
2. 研究优秀项目的架构设计：

   - Next.js的文件路由系统
   - Supabase的实时数据同步
   - Vercel的边缘部署架构
3. **刻意练习"拆解"**
4. 看到一个复杂系统，尝试画出它的模块图：
5. 电商系统拆解：
├── 用户模块（注册、登录、个人中心）
├── 商品模块（展示、搜索、详情）
├── 购物车模块（添加、修改、结算）
├── 订单模块（创建、支付、物流）
└── 后台模块（商品管理、订单管理）
6. **做完整项目，而不只是做功能点**
7. 从"会做一个登录功能"到"能做一个完整产品"，中间隔着系统设计能力的鸿沟。

---

### 维度3：人机协作深度

**定义**：知道什么时候用AI、怎么用AI、用哪个AI、怎么验证AI的输出。

这是一种新的**元技能**，会随着AI的发展变得越来越重要。

**怎么提升人机协作深度？**

1. **尝试不同的AI工具，了解它们的特点**
2. **王欢的工具矩阵**：
3. 新项目原型：Cursor + Lovable
理解代码库：Gemini CLI
复杂重构：Claude Code
日常开发：Cursor
精准修改：Codex CLI
4. **学习prompt工程，让AI更好地理解你**
5. 好的prompt能提升10倍效率：
6. ❌ **差的prompt**：
7. "帮我做一个登录页面"
8. ✅ **好的prompt**：
9. "创建一个登录页面，要求：
1. 支持邮箱+密码登录
2. 支持Google OAuth
3. 有"忘记密码"链接
4. 登录失败显示错误提示
5. 成功后跳转到/dashboard
6. 使用Tailwind CSS，风格现代简洁
7. 适配移动端"
10. **培养"验证"的习惯，不盲信AI输出**
11. AI生成的代码/内容，必须验证：
12. **代码验证清单**：

    - [ ] 能运行吗？
    - [ ] 逻辑正确吗？
    - [ ] 边界情况考虑了吗？
    - [ ] 安全问题处理了吗？
    - [ ] 性能够好吗？

### 公式的威力：乘法效应

为什么是**乘法**而不是加法？

因为任何一项为0，结果就是0：

**示例1**：技术很强，但问题定义力为0

一个开发者技术很强，能用AI快速实现功能。

但他不知道做什么，只能接外包需求。

核心竞争力 = 0 × 高 × 高 = 0

**示例2**：想法很多，但人机协作深度为0

一个创业者有很多想法，也能拆解问题。

但不会用AI工具，只能外包开发，成本高、效率低。

核心竞争力 = 高 × 高 × 0 = 0

**示例3**：三者都具备

一个产品经理：

- 能发现用户痛点（问题定义力：高）
- 能设计产品架构（系统设计能力：高）
- 会用AI快速实现MVP（人机协作深度：高）

核心竞争力 = 高 × 高 × 高 = 极高

**所以，未来的高手是这样的人**：

- 你能定义一个好问题（人的智慧）
- 你能设计一个系统架构（人的能力）
- 你能指挥AI去落地（人机协作）

## 5.4 三种必备的思维模式

### 思维模式1：批判性思维

**定义**：独立思考，质疑和验证信息的能力。

AI会犯错，会产生幻觉（编造事实），会有偏见。

你必须能识别这些问题，不能盲信AI的输出。

这种能力在AI时代不是变得不重要了，而是**更重要了**。

因为AI让获取信息太容易，辨别信息真伪反而成为稀缺能力。

**实操建议**：

1. **AI给出的事实性信息，用搜索引擎验证**
2. 不要直接采信AI说的数据、时间、人名等。
3. **AI给出的代码，先读懂再使用**
4. 不要复制粘贴了事，要理解每一行在做什么。
5. **AI给出的建议，思考它的前提假设是否成立**
6. **示例**：
7. AI建议："使用Redis缓存提升性能"
批判性思考：
\- 我们的性能瓶颈真的是数据库查询吗？
\- 引入Redis的复杂度值得吗？
\- 有没有更简单的方案？

---

### 思维模式2：系统思维

**定义**：理解事物之间的相互关系，掌握整体架构。

AI擅长局部优化，人负责全局设计。

你得能看到Big Picture，知道各个部分怎么配合。

**实操建议**：

1. **画系统图：输入→处理→输出→反馈**
2. **示例：内容创作系统**
3. 输入：灵感、素材、需求
  ↓
处理：AI辅助创作、人工润色
  ↓
输出：文章、图片、视频
  ↓
反馈：用户阅读、评论、数据分析
  ↓（闭环）
优化：根据反馈调整内容策略
4. **思考二阶效应：A改变了，会影响B，B又会影响C**
5. **示例**：
6. 决策：降价促销
一阶效应：销量增加
二阶效应：利润下降
三阶效应：品牌价值受损
7. **关注系统的瓶颈，而不是每个部分的最优**
8. **示例**：
9. 团队效率低：
\- 不是因为每个人不够努力
\- 而是因为沟通机制有问题（瓶颈）
优化瓶颈 > 优化个体

---

### 思维模式3：创造性思维

**定义**：提出新观点、新方案，把知识应用于新情境。

AI善于组合已有的东西，给你已知问题的已知答案。

但真正的创新——提出新问题、创造新东西——这还是人的专长。

**实操建议**：

1. **刻意做"跨界联想"**
2. A领域的方法能不能用到B领域？
3. **王欢的案例**：
4. 从"工业化生产"联想到"AI生成剧本杀"
从"微创手术"联想到"精准代码修改"（Codex CLI）
从"生产线"联想到"多智能体写作系统"
5. **保持好奇心，多问"如果……会怎样？"**
6. **示例**：
7. 如果AI能理解上下文10倍的信息，会怎样？
  → 诞生了Gemini CLI

如果AI能自主决策，会怎样？
  → 诞生了Claude Code

如果内容能一键多平台发布，会怎样？
  → 诞生了OmniPost
8. **允许"无用"的探索，创意往往来自意外**
9. 不要每件事都追求ROI。有些探索在当下看起来"没用"，但可能在未来连接成线。

## 5.5 场景和数据：玩具和产品的分水岭

做了20个项目后，我有一个越来越深的体会：

**没有场景的技术是空洞的，没有数据的产品是无力的。**

### 什么是"场景"？

场景就是：**谁，在什么时刻，因为什么原因，需要这个东西。**

很多人做产品，只想着功能：

> “我想做一个XXX工具”

但他们没有想清楚：

> “谁会用？什么时候用？为什么用我的而不是别的？”

**一个好的场景描述**：

> “农村诊所的医生，每天接诊几十个病人，还在用手写病历。他们需要一个简单的工具，用语音录入，自动生成结构化病历，节省时间。”

这就是王欢做"医语轻记"时的场景定义。场景清晰了，功能设计、交互设计、推广策略都会变得清晰。

### 什么是"数据"？

数据有两层含义：

**第一层：产品需要的数据**

比如：

- 一个AI学习路线平台，需要有高质量的学习资源数据
- 一个AI项目评估系统，需要有评估维度和评分标准数据
- 一个剧本杀生成工具，需要有角色模板、剧情模式数据

**没有数据的AI产品，就像没有食材的厨房。**

**第二层：产品产生的数据**

用户的行为数据、反馈数据、使用数据。

这些数据能帮你：

- 验证假设：用户真的在用吗？用哪些功能？
- 改进产品：哪里卡住了？哪里体验差？
- 形成壁垒：数据越多，产品越好，用户越多，形成飞轮

### 王欢的建议

如果你想从"做玩具"进阶到"做产品"，一定要问自己这两个问题：

1. **场景是什么？** 谁，在什么时刻，因为什么原因，需要这个？
2. **数据从哪来？** 产品需要什么数据？怎么获取？怎么积累？

这两个问题想不清楚，产品就会"飘"。

想清楚了，很多决策会自动变清晰。

# 第七章：常见问题FAQ

## Q1：我完全不会编程，真的能学会吗？

**A：能。**

Vibe Coding的核心就是"用自然语言告诉AI你想要什么"。你不需要会写代码，你需要的是：

- 能清晰表达你的需求
- 能验证结果是否符合预期
- 能在遇到问题时描述问题

这些能力和是否会编程无关。

**建议**：从最简单的项目开始（比如个人简介页），体验一次"从无到有"的过程。你会发现没有你想象的那么难。

---

## Q2：AI工具这么多，我应该从哪个开始？

**A：随便选一个，先用起来。**

如果你非要一个明确答案：

- **完全零基础**：Lovable或Bolt
- **想稍微深入**：Cursor
- **有一定经验**：Claude Code

但真的，选哪个不重要。重要的是**开始用**。

---

## Q3：我做的东西总是有bug，怎么办？

**A：有bug是正常的。**

bug是学习的机会。每一个bug都会教你一些东西。

处理bug的步骤：

1. **描述问题**：把你看到的现象清晰地告诉AI
2. **提供上下文**：相关的代码、错误信息
3. **让AI分析**：AI通常能定位问题
4. **验证修复**：确认问题真的解决了

**如果同一个问题反复出现**，说明你需要理解底层原因，而不只是让AI修复表面症状。

---

## Q4：我应该花多少时间学习？

**A：取决于你的目标。**

- **业余爱好**：每周3-5小时，持续3个月，可以做出简单作品
- **认真学习**：每周10-15小时，持续3个月，可以做出完整产品
- **全力投入**：每天4-6小时，1个月就能有明显进步

**关键不是时间长短，而是持续性。**

每天1小时，坚持3个月，比一周突击20小时然后放弃要有效得多。

---

## Q5：我学了一段时间，感觉没有进步怎么办？

**A：检查这几个方面：**

1. **是否在做项目？** 看再多教程，不如动手做一个项目
2. **项目是否有挑战？** 如果太简单，你不会成长
3. **是否有反馈？** 把作品发出来，收集反馈
4. **是否有复盘？** 做完一个项目，总结学到了什么

**"高原期"是正常的。** 学习不是线性的，会有平台期。坚持下去，突破会来的。

---

## Q6：AI生成的代码能用在正式项目/工作中吗？

**A：能，但要注意几点：**

1. **质量把关**：AI生成的代码需要人工审核
2. **安全考虑**：敏感信息（API Key等）不要让AI看到
3. **版权问题**：了解你使用的AI工具的服务条款
4. **测试**：AI生成的代码和手写的代码一样，需要测试

**建议**：先在个人项目中大量使用，熟练后再用于工作项目。

---

## Q7：怎么判断一个项目值不值得做？

**A：问自己三个问题：**

1. **是否解决真实问题？** 不是"我觉得有人需要"，而是"我确定有人需要"
2. **你是否是目标用户？** 如果是，你会更有感觉，更容易做好
3. **你是否愿意长期做？** 如果只是一时兴起，可能做不完

**一个快速验证方法**：把你的想法告诉10个人，看他们的反应。如果有3个人以上说"我需要"，值得做。
