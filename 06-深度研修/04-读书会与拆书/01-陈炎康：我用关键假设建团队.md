# 关键假设1：假设我可以低成本复制自己的研发和项目管理能力，这样我就可以专注于自己在商业能力上的成长。

## 目标

2018年回国创业，第一次需要开始自己做招聘，自己带领团队。摆在我面前的是一个极其重要的问题：如何务实地精益地培养和管理团队？让尽量小尽量低成本的团队完成尽量多的工作，同时让自己积累足够的团队管理经验，带领团队一步步稳扎稳打地提升团队规模和业务能力。

## 调研

当时看了很多人力资源管理和项目管理的文章和模型。胜任力冰山模型，KSAO任职资格模型，PMP项目管理体系，华为 IPD 体系，等等

看完以后，确实有了很多的想法，但是如果要直接按照这些方法去落实，都很重，成本很高。短期内的核心目标还是要尽量低成本高质量完成高回报率的研发业务。

## 一连串的自问

1.很朴素的一个自问：我为什么现在要招人？

答案很简单，因为项目开始多了，我自己忙不过来。

1.紧接着问自己：如果现在我有足够的时间和精力，我还需要招人吗？

答案也很直接：不需要，因为这些项目我自己有能力独立完成。

1.再接着问自己：那现在我如果当一个教练，教会一个人来分担相对简单但是又很耗时的一部分的研发工作可以吗？

答案：我不确定。我假设可以，需要去验证。

## 开始实验

### 实验前准备：拆我的工作流

当时手上三个项目，一个牵涉 iOS 应用开发 + 深度学习的算法研发，另一个是将一些深度学习算法优化部署在 Intel Movidius 芯片的计算嵌入式硬件上，还有一个 Web 3D 产品配置器的应用开发。

除了和甲方是远程合作之外，总体和2016-2018年间，我个人在微软工作的大致流程差不多。这个在另个作业里拆过，直接引用一下。

 1.和产品部门 PM 沟通，获取他们需要使用 AI 的需求场景。

2.和产品部门设计沟通，确定 story board 和需要新增的 UX/UI 原型。

3.和 研究院沟通，获取他们研发中的 AI 模型（是图像视频类处理的深度学习的模型，不是现在的大语言模型）。

4.和产品部门开发沟通，确定之后在现有产品中工程化集成的方案。

5.和有训练数据的内部部门或外部机构沟通，获取需要训练模型的数据。

6.执行研发工作：

a.第一个循环：数据工程 - 模型训练实验 - 结果验证

b.第二个循环：工程化 AI 模块设计 - 开发 - 测试

c.第三个循环：UI/语音交互模块设计 - 开发 - 测试

d.第四个循环：完整产品集成设计 - 开发 -测试

7.期间需要汇总 PPT 向往上两级的 Director 汇报。

如果是硬件类产品，还需要：

1.和 Intel 技术支持团队沟通，确定芯片的选型和参考载板设计。

2.和印度的硬件供应商沟通，从确定载板的设计细节到测试验收硬件原型。

 想找一个人直接复制所有能力，我不太清楚成功率有多高。于是从小处开始，按现在来看就是继续细化拆假设。

我个人的能力分配：

•开发能力：40%

•研发能力：30%

•项目管理能力：20%

•商业能力：10%

那就从我的前两大能力开始复制。开发能力在市场上较容易找到人才，研发能力则相对较难一些。而我自己更想在管理和商业上进一步精进。

### 第一轮实验：验证可以复制 3D 点云数据分析研发能力给一个没有做过研发的 3D 开发人员

工作中，很大的一块需要实时显示和展示重构出的 3D 空间，专业的词叫：数字孪生会议室。这里牵涉大量的 3D 点云数据处理，实时 3D 网格构建，实时 3D 材质贴图，实时 3D 渲染。甲方要求在浏览器中实现完整的客户端展示。

做了个市场调研，当时2018年，在合肥，如果招聘一个硕士或博士学位，有3D点云处理算法工程经验的人才，且不说月薪可能要1.5w-2w，关键这样的人而且还在求职太少了。

正好当时手上还有另一个网页 3D 产品配置器的小项目，于是决定这一轮就验证一个小假设：Web 3D 的人才经过培养可以快速接手 3D 数据的处理工作。

从Web3D配置器项目中，抽出了一个难题作为面试题：

有一个几百万点的工业设计模型，如何在网页中，用手机也可以顺畅显示？

一个月，仅有3人来面试，第3位是一个有8年经验的 3D 游戏开发工程师，给出了很有潜力的方案。由于女朋友在合肥，自己辞了上海的工作，回合肥后找了一份工作但是一直不很满意。技术能力和思维能力都不错，但是由于是大专学位，很难进入头部企业就职。也能接受不足1w的月薪。

入职后，一周内完美解决了上述工程问题。于是，我抛给他一个研发任务：要在苹果手机上实现三维点云的 RANSAC 平面拟合。

RANSAC（Random Sample Consensus / 随机抽样一致性）算法，他从未接触过，数学能力也有限无法理解各种网上资料的描述。我告诉他：不要把这个问题当成一个数学问题来看，当成一个数据进出流程来看。你着重看流程，看别人实现的代码，画流程图。关注每一步的输入和输出。

一个下午的时间，流程图出来了。又是一个下午的时间，iOS 版 RANSAC 算法出来了。他再回头看那些数学公式，全懂了。

之后又让他看了一些 PCL 库中的其他三维点云算法，在迁移至 iOS 前现在 Python 上直接用 PCL 库做实验。

哈哈哈！一切都很顺利，第一轮验证成功。

### 第二轮实验：验证可以复制 CNN 卷积神经网络的迁移学习能力给 App 开发工程师

Web3D UI开发，3D渲染优化，大量 3D点云数据采集与处理实验，一号员工的工作已几近饱和。手上项目的研发以及开发工作还有另外两大块可以立即分出去：跨平台的 App 全栈开发和 CNN 卷积神经网络的迁移学习训练。

于是2018年底又开始新一轮招聘，同样，不去找有 CNN 卷积神经网络的迁移学习训练经验的高薪人才，而是找有应用全栈开发经验的人员，培养他既可以做工程开发 App，也可以做研发去做神经网络的实验。

收到简历200多份，远程笔试题提交了50多份，筛选来面试的不到10人，面试最终筛选出1个人。只是我将「培养计划」写得太好，让他一度怀疑我们是打着招聘幌子来招生的不良培训机构。

同样的策略，先做舒适区的工作，再将非舒适区的工作拆成可以实操的执行方法，最后返回头去学习理论基础。带着他们看完了谷歌出品的机器学习工程师课程。基本上遇到企业数据、图像处理的场景都可以从数据采集、数据清洗、深度学习模型几个方向去设计和进行研发实验。同时，基于他们之前舒适区的能力，可以同时进行开发工作。

这两轮验证基本上确定了：我可以将自己的研发能力复制给没有研发经验的开发人员。

### 第三轮实验：假设我能将自己的项目管理能力复制给有跨行业设计思维的人，并且能在项目管理上超过我自己。

2019年，开始接了国内的项目订单。我想进一步去专注扩展业务渠道，学习商业分析和企业经营，不想把自己困在项目的管理上。所以国内的项目，我需要项目经理帮我去对外对接需求与交付，对内管理看板和团队进展。

将自己的项目管理能力复制出去，相对不难。因为我自己并没有很深的项目管理能力积累，会的也就是在微软工作中学会的工作拆解和看板管理。自己的原型设计能力都还是半吊子。风险管理、成本管理、团队管理、商业分析等自己都还在学习中。

难的是要让PM超过自己。于是在招聘的时候，我首要的要求是原型设计能力要超过我自己。这次并没有公开招聘，之前投简历在笔试过程中被淘汰的，有两个设计出身自学开发的人，我准备先试试。沟通后，一个小伙伴吸引了我的注意。他之前做过各种行业的各种工作，后来是自学的UI设计，在上一轮求职中后来去了一家电商企业修图，但是还是想进入互联网等技术企业长期发展。设计作品集看着还不错，能打60分（我给自己的设计作品顶多打30分）。但是，对我这边暂时没有很信任，持观望态度。当时有个朋友推了个在英国留学的学生想创业做个 App，我本来是想拒绝了的。他坚持转了我 1K 美金让我帮忙先设计一下。这不是巧了吗？正好我要试一下这个小伙伴。于是参考之前微软的原型设计规范，简化了一个我们自己的原型设计规范。将需求文档和原型规范发给了这个小伙伴，让他3天内设计出一个原型，沟通迭代后，再用3天的时间做出完整的高保真设计。最终按交付情况给予对应的500-1000元人民币的报酬。算是有偿笔试了。过程中从需求沟通，到行业需求理解，到原型和UI/UX设计都还不错，至少比我强，决定招纳。

入职后，让他先从一个国外的项目管理网站上学习工作流程，翻译各种模版，用后和我反馈一起简化迭代流程和模版。几个国内的项目下来，效果还不错。后来，又进一步让他围绕质量管理的核心，做出了全套软硬件项目质量管理体系。之后他工作之余自学考了成考，考了PMP，现在工作之余正在自学读管理相关的研究生学位。

经过三轮实验基本上确定了：只要找到合适的画像，我可以将自己的能力低成本复制给没有相关经验的人，并在工作中取得远超他们自己预期的结果。

# 关键假设2：假设研发和项目团队可以低成本扩张并复制能力，这样我们就可以在多个行业开展合作业务实验

## 目标

合作了几个行业头部研究院，爻和智能越来越像一家研发项目外包公司了。但是，我对爻和智能的定位是：创业项目孵化基地。需要低成本低风险地扩张团队，让爻和智能可以在风险可控的同时，和更多的研究院合作去探索各个行业所谓的突破口。同时，在疫情漩涡中，尽管还有微软项目支撑现金流，但是心里清楚项目已接近尾声。国内几个行业的研发结果也很难跑通市场化。一旦项目空窗，希望企业仍然可以保持运作。

## 调研

看了国内外大多的外包企业，都是大面积铺人铺供应商，无论是销售还是项目还是研发。如果走这个路线，我大概率会把自己困死在一家外包企业的经营管理上。而外包企业，哪怕是边际成本较低的软件外包，本身也是规模不经济的。

一些头部大厂如IBM、Oracle等，确实是外包服务出身，后来渐渐孵化出来了跨行业的头部产品。

这时候是 2020 年初，几个月前刚学过一堂的4期复盘营。对关键假设和调研黑客已有认知，当在调研中找一些答案时，并不能直接放手做。更何况又是疫情，又是大甲方项目尾声。各个渠道线索倒是不少，只是项目体量越来越大，要求越来越高，这边的小工作室都总觉得不一定能吃下来。考虑成本，不要烧钱，在放手做前，先做低成本实验吧。

## 观察

为了制定实验方案，先从内部复盘和观察开始。先是拉了4个研发和1个PM开会，总结我们哪些研发和开发工作可以进一步自动化提升团队的效率的。通过复盘，我们提出了3个假设：UI开发、后台开发、数据标记。观察后发现这三个是我们工作流最稳定的，也是有对应的技术方案可以自动化的。

## 开始实验

### 第一轮实验：通过新人来验证

我们放低了招聘标准，直接招助理岗，并且招的是只有一年跨岗位工作经验的应聘者。观察她在UI开发、后台开发、数据标记几个工作上近乎傻瓜式执行。结论如下：

•UI开发可自动化的程度还是比较低，很多时候需要灵活变通。

•后台开发，除了用户权限需要根据业务调整，之后的所有部分完全可以从数据库的结构自动生成 CRUD 完整流程。并且只需对市面上开源的工具做一些修改即可。

•数据标记，可以通过无监督学习和自监督学习算法完成，但是最后还是要人工反馈一下。

### 第二轮实验：通过自动化脚本验证

让几位工程师开始做脚本自动化他们重复的工作

•UI开发可以按我们的原子式设计自动化生成部分组件样式代码，但是数据绑定、复杂交互逻辑等还是不行。可以部分提升效率，但是还是要人。

•后台开发，几乎完成了多种数据库从一个数据库定义文件自动生成后台CRUD代码和API接口。仅需再加一层鉴权安全保护。

•数据标记，可以用开源的无监督学习和自监督学习工具给出标记假设，然后人工审核验证。

### 第三轮实验：通过大学生验证那些不能脚本自动化的部分

剩下的工作，很难用“专家系统”式的脚本完成，如果硬要做成本较高。于是我们从2021年夏天，开始了针对大二学生的远程兼职实习招聘。用学生完成那些不能用脚本完成的工作。并且进一步将其他的研发和项目工作细分，培养大学生完成更复杂的工作。以下是在「苦练基本功」作业中分享的对应内容。

 2021年开始，我们做了个实验：研发人才从大二学生开始培养。起点是，我们全职的研发工程师在项目执行过程中，很难有时间继续精进。而我又需要有人分担起技术管理的工作，让我自己可以从项目技术层抽开，有更多精力去做企业层的工作。

我们大胆做个假设：将研发工作拆成大学计算机系专业课的作业，给予一定的培训、练习、反馈，大二学生可以完成这些“作业”。

于是从2021年夏天开始，我们陆陆续续线上、线下培养了近200名大二的学生。直到他们的工作在2023年开始被 AI 替代。

第一周

•学习：编程语言、编程范式。

•练习：读代码，评价代码。

•输出：代码评价报告。

没有通过第一周考核的，不会进入之后的学习和工作。

第二周：

•学习：Git 版本协同管理、UML业务建模。

•练习：团队协作完成一个小模块的 UML 建模和代码实现。

•输出：每组的 Git 仓库包含 - UML 建模文档，代码与注释。

没有通过第二周考核的，不会进入之后的学习和工作。

第三周：

•学习：分师傅具体学习某个方向的一个技术工具与规范标准。

•练习：一个模拟工作任务至少3轮迭代。

•输出：模拟工作任务在Git仓库的代码与文档提交。

没有通过第三周考核的，不会进入之后的学习和工作。

第四周往后：

•学习：分师傅具体学习某个方向的一个技术。

•练习：每周作业。

•输出：每周的代码与文档提交。

这个人力实验我们一个月一轮，每一轮10-20人，培养了近200名大二计算机系的学生兼职工作。工作使用的是奖学金机制，每一个任务多人提交，每个都会有代码审核回复，但是最终仅会选有效时间内质量最好的那一个用在项目中，并给予奖金激励。

在这个人力实验的基础上，我也和一两个技术负责人一起迭代了之前的研发能力模型。

一开始，我们从上一个阶段的五个能力的体系开始，用雷达图进行成长规划和评估，用于分配师傅和任务推送。

执行过程中，发现很难量化评估，需要进一步迭代。于是对于每个技能都给出了一个量化评价方法：

•引用代码仓库或文档库中最近的10次使用，将链接汇总通过内部邮件发送。

•每个链接后给出自评分数 0-2 分。0 = 没有链接或完全不符合规范，1 = 部分符合规范，2 = 完全符合规范。

•每个链接，三位研发评分 0-2 分。0 = 没有链接或完全不符合规范，1 = 部分符合规范，2 = 完全符合规范。

•每个链接，两位PM评分 0-2 分。0 = 没有链接或完全不符合规范，1 = 时效内部分符合规范，2 = 时效内完全符合规范。

•将10次的总评分加在一起，按满分 2x6x10 = 120，能力评分 = 总评分 x 10 / 120。

•将某一个方向，比如「项目能力」的所有能力值平均后就是0-10分的该能力评分。

•每个季度的述职均按这个框架进行。

###  第四轮实验：通过 AI 验证

2021年底 GitHub 发布了Copilot AI。有些聪明的实习生在2022年已经在用Copilot帮他们干活了。但是经过我们工程师测试，当时给实习生的“作业文档”直接给到 Copilot AI，50%的时候还是拿不到想要的结果，哪怕是进一步迭代。

2023年，Copilot已经进化到可以给出和实习生同等质量的结果。

到2024年已经完全替代之前的实习生，无需培训直接上项目。对于敏感的项目，我们也搭建了内网安全的私有编码大模型替代了 Copilot。

现在进行中的验证中，我们假设可以只给 PlantUML和说明文档，大模型可以生成复杂项目架构，并按反馈迭代。进一步在对话交互中完成细节的代码实现。
