# 拆书开始

# 一、Software Is Changing Again——软件正在从代码系统变成意图系统

### Karpathy 在 YC 《Software Is Changing Again》

把 AI 时代的软件变化概括为三层结构。

Software 1.0 是人类直接写下的代码。

Software 2.0 是神经网络权重，人类不再逐行写规则，而是通过数据和优化器训练出模型。

Software 3.0 是自然语言 prompt，人类开始用英文、中文等自然语言直接“编程”大语言模型。

### **“your prompts are now programs”**

软件不再只是工程师写出的代码文件，也包括模型权重、系统提示词、工具说明、上下文窗口、企业知识文档、权限规则、测试标准和人类反馈流程。

- 软件的边界正在从“代码层”扩展到“意图层”。
- 过去的软件，是把人类已经明确知道的流程写成代码。
- 现在的软件，是把人类的目标、标准、经验和边界交给 AI 系统，让它在一定范围内生成、调用、判断和执行。

**AI 时代的核心能力不是单纯写代码，而是把模糊意图变成可执行系统。**

### **Software 3.0：自然语言不是替代代码，而是覆盖在代码之上的新控制层**

- Software 3.0，并不意味着传统代码失效。
- Software 1.0 仍然负责确定性、稳定性和可验证性。
- Software 2.0 仍然负责感知、分类、生成和模式识别。
- Software 3.0 增加的是一种新的控制层：人可以用自然语言调度模型和工具。

因此，未来的软件系统不是“自然语言取代代码”，而是三种软件共存：

- 传统代码负责精确执行；
- 神经网络负责处理复杂模式；
- 自然语言负责表达目标、约束和策略。

Software 3.0 的变化，不是程序员不再重要，而是产品经理、运营、咨询师、销售、研究者、管理者的经验开始进入软件系统。

过去不会写代码的人，只能提出需求。

现在不会写代码的人，可以直接参与构建原型、定义流程、测试假设、生成工具。

**技术门槛下降以后，新的门槛会转移到三个地方：**

- 能否定义清楚问题；
- 能否提供高质量上下文；
- 能否判断结果是否成立。

### LLM 不是聊天机器人，而是新的计算平台

**LLM 是一种“new kind of a computer”。**

ChatGPT、Claude、Gemini 这类系统不应只被理解为聊天工具，而应被理解为一种新的计算平台。

它像 utility，因为智能正在通过 API 被计量、调用和分发。

它像 fab，因为训练前沿模型需要巨额资本开支、算力基础设施和研究秘密。

它像 operating system，因为模型开始管理工具、文件、记忆、上下文、权限、多模态输入和第三方应用。

如果 LLM 是新计算平台，那么商业竞争不只发生在应用层，也发生在底层模型、工具协议、上下文工程、身份权限、数据接口和 agent 生态层。

在 PC 时代，操作系统定义了应用生态。

在移动互联网时代，手机系统和 App Store 定义了应用分发。

在 AI 时代，模型、agent、工具接口、MCP、AGENTS.md、企业知识库和权限系统，正在共同形成新的操作系统层。

AI 公司不只在发布模型，也在发布工具调用、记忆、浏览器控制、代码代理、企业连接器和 agent 管理系统。

模型本身是能力。

工具接口是行动边界。

上下文是工作记忆。

权限系统是组织治理。

评估系统是可信度来源。

### **AI 产品的分水岭从“能生成”转向“能验证”**

一句话区分 demo 和 product：

### **“Demo is works.any(), product is works.all()”**

AI 产品早期很容易出现 demo 错觉。只要某一次生成结果看起来成立，就能形成传播效果。但产品不是一次性演示，而是稳定、重复、可控、可追责的交付系统。

**AI 生成能力越强，验证体系越重要。**

在软件开发里，验证相对清晰：代码能否运行，测试能否通过，部署是否成功，错误能否复现。

在营销、咨询、教育、销售、法务、医疗、金融等领域，验证标准更复杂，因为结果往往不是立刻可测的。

因此，AI 产品真正的壁垒会从“调用哪个模型”转移到“如何设计验证系统”。

**验证系统包括：**

- 输出标准；
- 测试样本；
- 反例库；
- 人工审核节点；
- 权限边界；
- 日志记录；
- 回滚机制；
- 异常报警；
- 持续评估。

AI 时代的产品经理和企业管理者，需要把“好结果”定义成机器可以检查、人类可以追责、组织可以复盘的标准。

只要没有验证系统，AI 只能停留在生成工具。

一旦有验证系统，AI 才能进入业务流程。

### 从全自动幻想转向部分自主系统

Karpathy 用 Iron Man suit 比喻 AI 产品：**它既增强人，也具备一定自主性。**

这对应一个更现实的产品方向：partial autonomy。

AI 产品不应只在“工具”和“完全自主代理”之间二选一，而应存在连续的自主性滑杆。

- 低自主性：AI 提供建议，人类执行。
- 中自主性：AI 生成草稿，人类审核。
- 高自主性：AI 执行动作，关键节点请求确认。
- 更高自主性：AI 持续运行，只在异常时上报。

这一路径比“完全自动化”更接近真实商业落地。

企业采用 AI 的过程，不会从人工工作直接跳到无人系统，而是把某些环节逐步从人工执行变成 AI 生成、AI 初审、AI 执行、AI 监控、人工兜底。

因此，AI 产品设计的核心问题不是“能不能无人化”，而是“在哪些节点保持人类控制，在哪些节点允许机器自主”。

自主性不是越高越好。

自主性必须和任务风险、错误成本、验证难度、权限范围相匹配。

### Build for Agents：互联网和企业系统正在出现新的使用者

一个新的类别：

**“new category of consumer and manipulator of digital information”**

过去数字系统主要面向两类对象：

- 人类通过 GUI 使用软件。
- 计算机通过 API 调用软件。

现在出现第三类对象：AI agents。

Agents 不是传统 API 调用方，也不是普通人类用户。它们读自然语言、读文档、调用工具、执行步骤、处理错误，并需要上下文来理解任务。

这会改变软件和企业文档的写法。

README 是写给人看的。

API 文档是写给程序看的。

AGENTS.md、llms.txt、MCP 工具说明、Markdown 文档，是写给 agent 看的。

**这意味着未来企业会有三套界面：**

- 给人看的界面；
- 给系统调用的接口；
- 给 AI agent 理解和执行的上下文层。

网站、文档、SOP、知识库、销售话术、客服政策、风控规则、代码仓库，都需要被重写成 AI 可读、可调用、可验证的格式。

企业数字化的下一步，不是简单上线更多软件，而是把企业流程改造成 agent 可以安全参与的结构。

# 二、其他大神对的延伸

### Ethan Mollick ：管理成为新的编程能力

Ethan Mollick 《Management as AI Superpower》中把 AI agent 时代的核心能力指向管理。

### “talent is abundant and cheap. What’s scarce is knowing what to ask for.”

如果 prompt 是程序，那么管理就是编程。

如果 agent 是执行者，那么委派任务就是新的软件接口。

如果 AI 可以快速生成结果，那么人类的稀缺性就转移到目标定义、任务拆解、反馈修正和结果判断。

传统管理中的文档形式——产品需求文档、导演分镜、建筑设计意图、军事任务命令、咨询项目交付范围——都可以成为 agentic work 的提示结构。

这些文档共同解决同一个问题：把一个人脑中的意图转化为另一个执行者的行动。

**AI agent 时代，企业内部长期被视为“软能力”的东西会变成硬资产：**

- 任务定义；
- 交付标准；
- 反馈机制；
- 专业判断；
- 行业框架；
- 复盘习惯；
- 组织文档。

不懂技术的人可以通过这些能力调动 AI。

懂技术但缺乏业务判断的人，也会受到限制。

### **Satya Nadella 的延伸：知识工作者会变成“无限心智”的管理者**

Satya Nadella把 AI 时代的知识工作形态描述为：

**“manager of infinite minds”**

他还提出一个操作层面的表达：

**“macro-delegate and micro-steal”**

这意味着知识工作正在从亲自完成任务，转向宏观委派、微观介入、并行监督。

一个人可以把任务交给多个 agent 并行处理，同时在人类判断必要的节点插入反馈。

这种工作方式改变了知识工作的基本结构。

过去一个人完成一个任务。

后来一个人使用多个软件。

现在一个人可能同时管理多个 AI agent。

**这会带来新的组织问题：**

- agent 是否需要独立身份；
- agent 能访问哪些数据；
- agent 的操作如何审计；
- agent 生成的内容如何追踪来源；
- agent 犯错时责任如何归属。

Nadella 提到，组织里最重要的问题之一是：

**“who did what to whom”**

这说明 AI agent 进入企业以后，问题不再只是效率，而是身份、权限、来源、审计和治理。

AI agent 不是普通插件。

它一旦开始代表人行动，就必须进入企业的权限和责任体系。

### Bret Taylor ：AI 时代企业软件的原子单位是 agent

## “The atomic unit of AI is the agent.”

过去 Web 的基本单位是网站。

移动互联网的基本单位是 App。

AI 时代的基本单位可能是 agent。

如果这个判断成立，企业软件的竞争单位会发生变化。

过去企业购买的是 CRM、ERP、客服系统、财务系统、营销系统。

未来企业可能购买的是销售 agent、客服 agent、财务分析 agent、合同审查 agent、供应链 agent、培训 agent。

这不是简单把聊天框放进旧软件里，而是把一段业务流程封装成一个具备上下文、工具、权限和目标的执行单元。

企业软件也可能从“卖座席”转向“卖结果”。

过去 SaaS 按用户数收费。

AI agent 更接近按任务、按流程、按结果、按调用量收费。

这会冲击传统 SaaS 的产品形态和商业模式。

### Dario Amodei 的延伸：AI 的深层作用是压缩时间

Dario Amodei 在《Machines of Loving Grace》中

### **“compressed 21st century”**

他预测，在生物医学等领域，AI 可能把人类未来 50 到 100 年的进展压缩到 5 到 10 年。

也可以理解为：AI 的核心作用不是简单节省时间，而是提高试错频率。

过去一个团队一周做一次方案。

现在一个人可以一天生成、比较、测试多套方案。

过去一个产品从想法到原型需要数周。

现在原型可以在小时或天的尺度内出现。

过去组织学习依赖会议、汇报和人工总结。

现在 agent 可以持续记录、分析、复盘和生成下一步行动。

AI 压缩的不是单个动作的时间，而是从想法到反馈的周期。

增长速度的变化，不来自单点效率提升，而来自循环速度提升：

- 提出假设；
- 生成方案；
- 测试反馈；
- 修正方向；
- 再次生成；
- 再次验证。

当这个循环被 AI 加速以后，行业竞争会从资源竞争转向学习速度竞争。

### Sutton 的延伸：不要把 AI 理解成“人类经验的自动化”

Richard Sutton 在《The Bitter Lesson》。AI 研究史反复显示，长期最有效的是能够利用计算扩展的一般方法，而不是把人类专家经验手工写进系统。

Software 3.0 不是把人类经验原封不动写进 prompt，也不是让企业把旧 SOP 复制到 AI 里。

更准确的方向是：把人类经验变成 AI 能使用的上下文、工具、反馈和评估环境，让系统通过更多计算、更多尝试、更多反馈产生改进。

因此，AI 改造企业不是“把旧流程自动化”，而是重新设计流程，使它能够被模型、工具和反馈循环持续优化。

旧流程自动化，只会得到更快的旧流程。

新流程重构，才会释放 AI 的计算优势。

# **三、AI时代的护城河不是品味，是能量**

**出处：公众号《不懂经》**

### **品味的幻觉**

硅谷把"personal taste is the moat"当咒语念，以为AI接管执行层后，"选哪个更好"就是人最后的价值。这是一阶思维错误。

水野学给品味下过精确的定义：品味，是使无法量化的现象表现出最佳样貌的能力。

关键词是"无法量化"。

硅谷正在做的事，是把品味翻译成效能语言，塞进OKR，写进融资计划书。把一种本来无法量化的东西强行量化，这不叫重视它，这叫杀死它。

**品味的三重死亡**

**死亡一：从过程退化为标签。**

品味需要漫长的试错——穿过不合身的衣服，听过错误的乐队，买过后悔的家具，然后慢慢知道自己适合什么。今天没有人愿意经历这个阶段。

算法告诉你什么有品味，KOL兜售成套的"品味包"，你只需要订阅，不需要经历。

有品味已经等同于有好品味，人们害怕的不是没品味，而是"显得没品味"。品味从内在过程退化为外部标签。

**死亡二：从做东西退化为选东西。**

品味不是"我喜欢什么"，而是能说清楚"为什么这个符合目标"。后者需要你曾经亲手做过。

**一个只在AI对话框里选东西的人，永远不会获得判断。**AI生成一百个选项，你挑出最好的那个，不是在发挥品味，你只是在消费。你用越来越多的选项，掩盖越来越弱的判断力。

**死亡三：从指向世界退化为关于自我的表演。**

 桑塔格说，品味管辖着每一种自由的人类反应，与机械反应相对。品味的价值恰恰在于它不是关于你自己的。但今天品味已完全变成"我是谁"的表演。

人们不是在消费作品，是在消费"消费这个作品"所带来的身份信号。消费力不管你消费的是爱马仕还是小众独立电影，永远不构成护城河。

判断力需要代价。

### **品味背后是判断力**

乔布斯被供奉为品味之神，但他的遗产不是品味，是判断。

1997年回归苹果第一件事不是定义美学方向，而是砍掉百分之七十产品线。砍掉七十款产品不需要品味，需要的是勇气，是你愿意为这个决定承担后果。AI能生成一百套方案，但不能替你承担砍掉七十套的后果。

里克·鲁宾不会任何乐器，做了四十年，靠的是对自己判断力的自信。乔布斯说真正的艺术家发货，鲁宾说创造力是注意的行为。**判断力的唯一来源，是在真实世界里反复做东西、发东西、被否定、再做的循环。品味只是这个循环的副产品。**

### **能量才是终极护城河**

既然做东西是形成判断力的唯一途径，为什么大多数人不去做了？

做东西需要能量——好奇心是能量，注意力是能量，忍受不确定性的能力是能量，被否定之后还有力气继续做的能力是能量。AI让信息端发生核爆，信息生产成本趋近于零，价值迅速稀释。但能量端没有。

你做一个东西需要的时间、注意力、心理成本、承担的风险，不会因为AI减少。当所有人都能用AI秒出内容，真正拉开差距的，是你愿不愿意再多花三个小时、三天、三周，把它改到对为：

品味是你以为你有的东西。

判断是你实践出来的东西。

能量，是你决定把这一生投进什么地方。
